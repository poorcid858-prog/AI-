# 任务包 F：运营中心（新功能，高优先级）

## 问题描述
缺少"运营中心"功能。运营人员需要能查看所有用户的聊天数据、分析AI的回答质量、追踪知识库的使用情况。

这个功能需要与"知识库四层架构"配合使用。

## 产品设计

### 运营中心的三大功能模块

#### 1. 聊天记录查询（Chat History）
**说明**：运营人员可以查看所有用户的聊天记录

**主要功能**：
- 查询所有聊天记录（有权限控制）
- 按用户筛选
- 按日期范围筛选
- 按关键词搜索
- 导出聊天记录
- 查看聊天上下文

**UI设计**：
- 搜索和筛选区域
- 聊天记录列表（表格）
  - 用户名
  - 提问内容（前100字）
  - AI回答（前100字）
  - 提问时间
  - 是否引用Chunk
  - 用户满意度（如果有反馈）
- 分页

#### 2. Chunk追踪与溯源（Chunk Tracing）- **核心功能**
**说明**：每条AI回答都记录使用了哪些Chunk，运营人员可以通过点击Chunk跳转到知识库进行溯源和修复

**主要功能**：

**2.1 聊天时记录Chunk引用**
- 当AI回答时，自动记录使用的Chunk ID
- 记录关联度评分（AI是如何相关性排序的）
- 记录Chunk的出现位置（在回答中的第几段）

**2.2 聊天记录中显示Chunk**
- 在聊天记录中，AI的回答旁边显示使用的Chunk ID列表
- 可展开查看Chunk的预览内容
- 点击Chunk ID 可以跳转到知识库的【Chunk详情页】

**2.3 知识库追踪视图**
- 在知识库的Chunk详情页显示：
  - 这个Chunk被引用了多少次
  - 最近一次被引用的时间
  - 用户对包含此Chunk的回答的满意度
  - 如果用户给了反馈，显示反馈内容

**2.4 反向修复**
- 如果发现某个Chunk的内容不好，或者用户反馈不满意
- 运营人员可以：
  - 直接编辑Chunk内容（需要权限）
  - 标记Chunk为"需要更新"
  - 创建一个修复任务

#### 3. 分析统计（Analytics）
**说明**：统计和分析聊天数据，帮助运营人员了解系统情况

**主要功能**：

**3.1 高频问题统计**
- 统计用户最常问的问题（聚合相似问题）
- 显示提问频次和趋势
- 帮助发现用户的真实需求

**3.2 Chunk使用统计**
- 统计每个Chunk被引用的频次
- 显示最常用的Chunks（Hot Chunks）
- 显示最少用的Chunks（Cold Chunks）
- 帮助识别知识库的完整性问题

**3.3 AI回答质量统计**
- 统计用户对AI回答的满意度评分
- 显示满意度趋势
- 按问题类型分析满意度

**3.4 时间序列分析**
- 按时间聚合查看：每天、每周、每月的聊天量
- 按时间聚合查看：Chunk的使用热度变化

## 系统架构

### 数据库设计

需要创建以下表：

1. **chat_records** - 聊天记录表
   - id (主键)
   - user_id (用户ID)
   - user_name (用户名，冗余字段用于查询)
   - question (用户的问题)
   - answer (AI的回答)
   - chat_time (聊天时间)
   - chunks_used (使用的Chunk ID列表，JSON格式)
   - user_feedback (用户反馈：满意/不满意/无反馈)
   - feedback_score (满意度评分，1-5)
   - feedback_text (用户的反馈文本)

2. **chunk_usage** - Chunk使用统计表
   - id (主键)
   - chunk_id (Chunk ID)
   - chat_record_id (关联的聊天记录)
   - relevance_score (关联度评分)
   - position_in_answer (在回答中的位置)
   - used_time (使用时间)

3. **question_analysis** - 问题分析表
   - id (主键)
   - question_hash (问题的哈希值，用于聚合相似问题)
   - question_text (问题文本)
   - frequency (出现频次)
   - last_asked_time (最后一次被问的时间)
