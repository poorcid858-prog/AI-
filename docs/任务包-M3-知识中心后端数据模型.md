## 1. 任务描述

严格按《知识中心需求说明书_Agent实施版.md》重建知识中心后端数据模型。本包覆盖：
- **Document + DocumentVersion 文档与版本分离**
- **三元状态模型**（审核状态/处理状态/生效状态）
- **元数据继承链**

## 2. 需求要点（引用需求文档）

### 2.1 Document + DocumentVersion（需求第4节）
- "文档"是业务上的同一份知识；"版本"是该文档某一次具体内容
- `Document`: document_id, document_name, current_version_id, created_at, updated_at
- `DocumentVersion`: version_id, document_id, version_number, source_file_id, review_status, processing_status, online_status, metadata, created_at, updated_at

### 2.2 三元状态模型（需求第30节）
三个维度独立，不塞进一个字段：
- **审核状态**: 待审核 / 审核通过 / 审核失败
- **处理状态**: 未处理 / 处理中 / 处理成功 / 处理失败
- **生效状态**: 未生效 / 已上线 / 已下线

### 2.3 版本号规则（需求第5节）
- 未完成完整向量化处理 → 不展示版本号
- 只有完成正式知识处理、形成正式版本后才形成 V1
- 列表始终只展示当前最新版本

### 2.4 元数据继承链（需求第32节）
- 原始文档元数据 → 标准化文档继承 → Chunk继承 → Vector通过Chunk追溯

### 2.5 实体模型（需求第31节）
```
Document          { document_id, document_name, current_version_id, created_at, updated_at }
DocumentVersion   { version_id, document_id, version_number, source_file_id, review_status, processing_status, online_status, metadata, created_at, updated_at }
StandardizedDocument { standardized_document_id, document_id, version_id, content, processing_status, created_at, updated_at }
Chunk             { chunk_id, standardized_document_id, document_id, version_id, chunk_index, title, content, metadata, processing_status, created_at, updated_at }
Vector            { vector_id, chunk_id, document_id, version_id, embedding_model, dimension, vector, status, created_at, updated_at }
```

## 3. 修改清单

### 3.1 重写 `lib/knowledge-layers.js` 的核心数据模型
- 新增 `Document` 和 `DocumentVersion` 实体（用现有 JSON 文件存储）
- 现有 `raw_documents` 表改造为 `DocumentVersion` 的载体
- `std_documents` 表添加 `version_id` 和 `document_id` 字段
- `chunks` 表添加 `version_id` 字段
- `vectors` 表添加 `version_id` 字段
- 保持现有 `store.js` 的 JSON 文件存储方式
- 四层数据血缘：每层保留父级 ID（document_id → version_id → standardized_document_id → chunk_id）

### 3.2 重构状态管理
- `STD_STATUS` 从 8 种扁平状态改为三元状态模型
- `review_status`: pending / approved / rejected
- `processing_status`: not_processed / processing / success / failed
- `online_status`: not_online / online / offline
- 修改 `TRANSITIONS` 状态机校验逻辑适配三元状态
- 修改 `assertTransition` 校验逻辑

### 3.3 元数据继承
- 修改 `createStdVersion` 从 raw 继承完整元数据（含 knowledgeType, tags, validUntil）
- 修改 chunk 创建逻辑：Chunk 继承原始文档的完整元数据

### 3.4 数据兼容
- 检查现有 `lib/documents.js`、`lib/rag-engine.js`、`lib/vector-store.js` 是否仍能运行
- 若 break，则一并修复（保持全链路可用）
- 运行 `npm test` 确保现有测试不大量失败（如需修复测试，补齐新测试）
