# 任务包 E：知识库四层架构

## 问题描述
知识库应该有四层架构，每一层都能通过ID找到对应的上一层文档。这个架构是后续"运营中心"和"召回可观测"功能的基础。

## 四层架构设计

### 整体概念图
```
用户上传文档 → 第1层：原始文档 
              ↓（清洗、去重、规整、打标签）
           第2层：标准化文档
              ↓（按策略切分）
           第3层：Chunk（文档片段）
              ↓（向量化）
           第4层：向量化数据（Embedding）
```

### 第1层：原始文档（Raw Document）
**说明**：用户上传的原始文件

**存储内容**：
- 文件ID (doc_id)
- 文件名 (filename)
- 文件类型 (file_type: pdf, word, txt等)
- 文件大小 (file_size)
- 上传者 (uploader)
- 上传时间 (upload_time)
- 审核状态 (review_status)
- 原始文件内容/路径 (file_content/file_path)
- 元数据 (metadata: 作者、创建时间等)

**数据库表**: `documents`

### 第2层：标准化文档（Standardized Document）
**说明**：对原始文档进行清洗、去重、规整、打标签后的版本

**处理步骤**：
1. **清洗** - 去除特殊符号、多余空格、格式化文本
2. **去重** - 去除重复的段落和句子
3. **规整** - 统一格式、修复错别字、标准化术语
4. **打标签** - 添加分类标签、关键词、业务标签

**存储内容**：
- ID (standardized_doc_id)
- 关联的原始文档 (doc_id) - **关键：能追踪回上一层**
- 清洗后的内容 (processed_content)
- 标签 (tags: 数组)
- 关键词 (keywords: 数组)
- 分类 (category)
- 处理状态 (processing_status)
- 处理时间 (processed_time)

**数据库表**: `standardized_documents`

### 第3层：Chunk（文档片段）
**说明**：将标准化文档按指定策略切分成多个片段（用于检索和向量化）

**切分策略**（可配置，见任务包F）：
1. **按Token数量切分** - 每个Chunk最多N个Token（比如1000）
2. **按副标题切分** - 按一级、二级、三级副标题自动切分

**存储内容**：
- ID (chunk_id)
- 关联的标准化文档 (standardized_doc_id) - **关键：能追踪回上一层**
- 关联的原始文档 (doc_id) - **方便直接溯源**
- Chunk内容 (chunk_content)
- 位置信息 (position: 在原文档中的位置，比如第3页第2段)
- Chunk顺序 (chunk_order: 1, 2, 3...)
- 切分策略 (split_strategy)

**数据库表**: `chunks`

### 第4层：向量化数据（Embedding）
**说明**：对Chunk进行向量化处理（用于语义搜索和检索）

**存储内容**：
- ID (embedding_id)
- 关联的Chunk (chunk_id) - **关键：能追踪回上一层**
- 向量数据 (embedding_vector: 数组形式，比如1536维)
- 向量模型 (embedding_model: 用什么模型生成的向量，比如"text-embedding-3-small")
- 创建时间 (created_time)

**数据库表**: `embeddings`

## 追踪链路示例

当用户在运营中心看到AI引用了某个Chunk时，可以：

```
Chunk_ID: chunk_123
  ↓ (查 chunks.standardized_doc_id)
Standardized_Doc_ID: std_doc_45
  ↓ (查 standardized_documents.doc_id)
Doc_ID: doc_789
  ↓ (查 documents)
原始文档名: "产品设计规范.pdf"
原始文档内容: [下载或预览原始文件]
```

这样，从Chunk可以完全追踪回原始文档，用于溯源和反向修复。

## 当前项目的调整

### 现有的可能性
- 项目中可能已经有了原始文档和Chunk的概念
- 可能有了文档上传和向量化的功能
- 但缺少清洗、规整的中间层

### 需要做的调整
1. 理解现有的数据库结构
2. 添加"标准化文档"层
3. 在各层之间添加外键关系
4. 实现追踪逻辑
