## 需求背景

大多数 RAG 项目做到"能答"就停了，做不到"答错了能查、能修、能验证修好了"。本章是分水岭，也是这个项目最专业的部分。

## 功能描述

### 功能 1：检索快照（看得见）

每次 AI 回答，都留一条完整的检索快照，包含：

```
原始问题
   ↓
拆解结果            分词 / 停用词过滤 / 同义词归一后的关键字
   ↓
权限过滤前的候选    共 N 条
   ↓
权限过滤            剔除了哪些、因为什么（业务线 / 密级 / 状态）
   ↓
召回结果            每条带：相似度分数、来自哪份文档哪一章、
                    Chunk ID、入选或淘汰的原因
   ↓
重排后的最终选择    实际塞进提示词的是哪几条
   ↓
提示词全文          Skill + 角色设定 + 知识 + Few-shot 示例
   ↓
AI 输出 + 质量校验结果
```

**两个入口**：
- **单条**：历史记录里每条回答旁边一个"查看召回"按钮
- **整体**：AI 运营 → RAG 检索分析（召回率分布、常见零召回问题、高频引用片段排行）

### 功能 2：三种修复动作（改得动）

管理员看完召回详情发现问题后，三条修复路径：

| 动作 | 影响链路 | 用在什么场景 |
|------|---------|-------------|
| **改原始文档** | 重新加工 → 新版标准化文档 → 重新切分 → 重新向量化，旧版归档 | 内容本身就错了 |
| **调参数重新标准化** | 不动原文，重新生成标准化文档 + 片段 + 向量 | 内容对，但被切碎了/表格洗坏了/章节没识别对 |
| **删除文档** | 片段与向量连带失效 | 文档整体作废 |

**可调的标准化参数**：
- 切分粒度（按章节/按段落/固定字数）
- 片段最小长度/最大长度
- 是否保留表格结构
- 是否把章节标题拼进片段正文（**对命中率影响最大的参数**）
- 清洗强度
- 去重阈值

### 功能 3：安全设计（必须做）

**① 执行前必须显示影响预览**

```
⚠ 此操作将影响：
   · 1 份标准化文档（v2 → 归档）
   · 37 个知识片段
   · 37 条向量
   · 其中 12 个片段在过去 7 天被 AI 引用过 45 次

   [ 取消 ]  [ 确认执行 ]
```

**② 重新加工不能直接覆盖，必须先出草稿版本**

调整参数 → 生成草稿版（不生效）→ 新旧并排对比 → 回归验证（拿历史问题重放）→ 确认发布 / 弃稿
