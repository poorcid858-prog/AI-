# 任务总览 K 系列 — 六大模块导航重构 + 问题修复（2026-08-16）

> 基于 PM 上线测试提出的 10 个问题（进展.md 已记录），拆解为 4 个任务包，按依赖顺序执行。
> **本批次目标是：按需求文档的 6 大一级模块 + 二级菜单重新组织前端，修复 PM 指出的问题。**

---

## PM 提出的 10 个问题（源需求）

1. 审核中心前端缺"发布"按钮（后端 API 已有）
2. 知识库应支持上传文档，而不是直接在页面粘贴文字
3. 知识库点进去后看不到菜单，无法回到一级菜单
4. 菜单分布未按需求文档 6 个一级菜单 + 二级菜单结构
5. 管理后台无法配置 AI 聊天中的提问模板（后端只有 GET，无 CRUD）
6. 能力中心、审核两个菜单点进去看不到页面信息（白屏）
7. 系统配置菜单点击后页面跳转但菜单 tab 未高亮
8. 系统配置里的"系统参数"含义不清、无实际作用
9. 系统配置里不应出现"分层 prompt"配置，Prompt 配置应在能力中心
10. 整体 UI 太丑，不像传统管理系统

## 页面结构目标（严格按需求文档 V2.0）

```
├── 1. AI工作台
│   ├── 产品助手 / 测试助手 / 前端助手 / AI对话 / 历史记录
├── 2. 知识中心
│   ├── 知识库 / 文档管理 / Chunk管理 / 知识检索
├── 3. 能力中心
│   ├── AI能力(聚合) / Workflow / Skill / Reference / Prompt / Tool/Script
├── 4. 审核中心
│   ├── 知识审核 / 能力审核 / AI结果审核
├── 5. 运营与管理中心
│   ├── 使用分析 / AI效果分析 / 能力运营 / 问题定位
└── 6. 系统管理
    ├── 用户/角色 / 权限管理 / 模型配置 / AI日志 / 系统配置
```

**布局**：左侧固定边栏（Bootstrap 5.3 深色），一级菜单展开二级子菜单。顶部品牌 + 用户区。

**核心机制**：`App.renderSidebar(moduleKey, itemKey)` 统一渲染左侧边栏，所有页面接入，标注当前激活项。菜单常驻（知识库等页面也能随时返回一级菜单）。

## 各任务包详细说明

### 任务包 K1：全局左侧边栏导航框架

**做什么**：
1. 新建 `public/js/sidebar.js` —— 通用左侧边栏渲染组件
   - 渲染 6 个一级菜单（AI工作台/知识中心/能力中心/审核中心/运营与管理中心/系统管理）
   - 每个一级菜单可展开显示二级子菜单
   - 按用户角色（admin/reviewer/产研/客服等）过滤可显示的菜单项
   - 高亮当前激活的一级项和二级项
   - 提供折叠/展开、收起侧栏的交互
2. 改造 `public/js/app.js`：`renderHeader(activeKey)` 重构为 `renderSidebar(moduleKey, itemKey)`，保留顶部品牌 + 用户区
3. 所有页面接入 `renderSidebar`，标注各自所属的模块/子项
4. 移除顶栏扁平导航，改为侧边栏
5. **验证**：知识库等页面侧边栏常驻，可随时返回任一菜单；各二级菜单页面能正确高亮

**涉及文件**：`public/js/sidebar.js`(新)、`public/js/app.js`、`public/css/style.css`、`public/css/sidebar.css`(新)、**public/*.html 全部页面**

**工作量**：5-6h｜难度：中

---

### 任务包 K2：提问模板管理（CRUD）

**做什么**：
1. 后端补全 CRUD 路由：`routes/admin.js` 增加
   - `POST /api/admin/prompt-templates`（新增）
   - `PUT /api/admin/prompt-templates/:id`（更新）
   - `DELETE /api/admin/prompt-templates/:id`（删除）
   - 复用 `lib/prompt-templates.js` 已有的 `create/update/remove`
2. `admin-config.html` 新增"提问模板"Tab（或卡片）：
   - 列表展示所有模板（名称/内容/适用角色/优先级/启用状态）
   - 新增/编辑/删除/启用-禁用操作
   - 最多 10 条，按产品/测试/前端/客服区分
3. 页面套用 K1 侧边栏

**涉及文件**：`routes/admin.js`、`public/admin-config.html`、`lib/prompt-templates.js`(微调，若需要)
**依赖**：K1 ✅
**工作量**：2-3h｜难度：低

### 任务包 K3：知识中心文件上传 + 白屏修复 + 审核发布按钮

**做什么**：
1. **真正的文件上传**：`knowledge.html` 的"上传新文档"从"粘贴 Markdown 文字"改为文件上传
   - 前端：文件选择控件 + 读取文件内容填入表单（涵盖 .md/.txt）
   - 后端：`routes/documents.js` 用 base64 或文本接收，`lib/documents.js` 支持
2. **审核发布按钮**：`review.html` 在文档审核通过（status=approved）且未发布时，显示"发布到 RAG 库"按钮，调 `POST /api/documents/:id/publish`
3. **白屏修复**：排查 `review.html`、`capability.html`（含 admin-capability.html）点进去无内容的原因并修复（脚本报错/数据为空/权限/路由），确保页面有内容展示
4. `admin-config.html` 移除"分层提示词"Tab（移到 K4 能力中心）和"系统参数"Tab（删/明确用途）
5. 页面套用 K1 侧边栏

**涉及文件**：`public/knowledge.html`、`routes/documents.js`、`lib/documents.js`、`public/review.html`、`public/capability.html`、`public/admin-config.html`
**依赖**：K1 ✅
**工作量**：3-4h｜难度：中

---

### 任务包 K4：Prompt 配置移入能力中心 + UI 全面美化

**做什么**：
1. **Prompt 配置移入能力中心**：能力中心新增"Prompt"子菜单，提供全局/角色/Workflow/Skill 分层 Prompt 的配置界面（复用 `admin-config.js` 现有逻辑，界面从系统配置迁移过来）
2. **系统配置瘦身**：只保留密码配置、Chunk 切分等有实际业务的配置
3. **UI 全面美化**：基于左侧边栏新布局重做各页面视觉
   - 统一卡片、表格（用 DataTables 插件）、按钮、表单样式
   - 整体贴近传统管理系统风格（信息密度、对齐、留白）
   - 消除各页面残留内联 `<style>`，收拢到全局 css

**涉及文件**：`public/capability.html`、`public/css/*.css`、`public/admin-config.html`、`lib/admin-config.js`
**依赖**：K2、K3 ✅
**工作量**：6-8h｜难度：高
