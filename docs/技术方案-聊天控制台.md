## 0. 上下文

- **背景**：现有 `public/workspace.html` 是"提交需求 → 看结果 → 再提交"的表单式 UI，PM 觉得不像 AI 控制台
- **目标**：进 AI 控制台 = 进聊天页，**像微信聊天**的体验
  - 左侧历史聊天列表
  - 中间对话流（用户/AI 交替）
  - 顶部下拉：岗位 / 业务线 / 常用问题（**按岗位变**，10 条）
- **新数据流**：
  - 每次对话**自动存档**到 `data/qa-history.json`（**与需求 1 共享**）
  - 跑 workflow 时除检索 chunks，还**按语义匹配** qa-examples.json 优秀问答对，**塞进 prompt 作为 few-shot**
- **关键约束**（PM 原话）：
  - 常用问题 = **各岗位出现频次 top 10**（按用户问得多的统计，**不绑优秀问答对**）
  - 优秀问答对 = **每次问答时按语义动态匹配**，**只**作为 prompt 的一部分（few-shot 池）

## 1. 数据模型

### 1.1 聊天历史 `data/qa-history.json`

```json
{
  "version": 1,
  "updatedAt": "2026-08-13T10:00:00Z",
  "records": [
    {
      "id": "qa_20260813_001",
      "userId": "u_001",
      "userName": "张三",
      "role": "product",
      "bizLine": "trade",
      "sessionId": "s_20260813_001",    // 一次会话（一组对话），多个 record 同 session
      "turn": 1,                          // 第几轮
      "type": "user" | "ai",
      "content": "我需要一个退款流程的PRD",
      "timestamp": "2026-08-13T10:00:00Z",
      "workflowId": "wf_xxx" | null,      // type='user' 时为发起的工作流
      "ragChunks": [...],                  // type='ai' 时存召回的 chunks（供需求 1 审计）
      "qualityScore": 8,                   // type='ai' 时的质量分
      "feedback": null | "up" | "down",
      "latencyMs": 1234
    }
  ]
}
```

- **设计要点**：
  - `sessionId` 区分多次"打开聊天窗"（关掉重开是新 session）
  - `turn` 是 session 内轮次
  - 一次工作流产生 2 条 record（user 问 + ai 答）
  - `ragChunks` 仅 ai 答时存（节省空间 + 加快列表加载）

### 1.2 常用问题频次 `data/qa-frequency.json`

```json
{
  "version": 1,
  "updatedAt": "2026-08-13T10:00:00Z",
  "byRole": {
    "product": [
      { "text": "退款流程PRD", "count": 12, "lastAsked": "2026-08-12" },
      ...
    ],
    "test": [...],
    "frontend": [...],
    "cs": [...]
  }
}
```

- **统计逻辑**：每次 user 提交问题时，更新对应岗位的 text 频次（text 经 `normalize(text)` 归一化：去空格、转小写）
- **取 top 10**：按 `count desc, lastAsked desc` 排序
- **种子数据**：上线时**预置 30 条**（4 个角色 × 7-8 条，PM 给），避免首次打开下拉为空

### 1.3 现有 qa-examples.json（**复用，不改**）

- 仍然是优秀问答对池
- **新作用**：每次 workflow 跑时，按用户问题**语义检索 top 3** 优秀问答对，**塞进 prompt** 作为 few-shot

## 2. 提示词改动（lib/prompt-engine.js）

### 2.1 当前 prompt 结构

```
[角色设定]
[Few-shot: 静态写死的 2-3 条示例]
[RAG 召回 chunks]
[Reference: 模板/字段规范]
[任务 + 用户需求]
[输出格式约束]
[边界约束]
```

### 2.2 改动后

```
[角色设定]
[Few-shot:
  - 静态示例 1-2 条
  - **动态 few-shot**: 从 qa-examples.json 按语义检索 top 3 相似问答（**不只匹配关键词，匹配整句语义**）
]
[RAG 召回 chunks]
[Reference: 模板/字段规范]
[任务 + 用户需求]
[输出格式约束]
[边界约束]
```

- **动态 few-shot 实现**：
  - 复用 `lib/vector-store.js` 的相似度计算（TF-IDF + 余弦）
  - qa-examples.json 的每条**预先向量化**（启动时或首次访问时构建索引，存内存）
  - 检索时取相似度 > 0.3 的 top 3（阈值防注入 / 噪声）
  - 格式：`[示例 Q]: ... \n [示例 A]: ...`
- **边界**：qa-examples 为空时**静默降级**（不报错，只用静态 few-shot）

## 3. 路由改动

### 3.1 新增

- `GET /api/chat/history` —— 历史聊天列表（按 sessionId 分组，最多 100 session）
- `GET /api/chat/frequency?role=product` —— 常用问题 top 10
- `POST /api/chat/send` —— 发新问题（**走原 workflow 链路**，但额外存档 qa-history + 更新 frequency）
- `GET /api/chat/session/:id` —— 单个 session 详情

### 3.2 改动

- `POST /api/workflow/run` —— **内部调用 chat/send**（兼容老接口，但推荐 chat/send）
- `lib/prompt-engine.js` —— prompt 组装加动态 few-shot
- `routes/workflow.js` —— 跑完 workflow 后**调用** lib/qa-store.js 存档

## 4. 前端改动

### 4.1 public/workspace.html（**大改**）

- **整体布局**：三栏
  - 左（20%）：**历史聊天列表**（按 session 分组，最新在上；点击切换）
  - 中（60%）：**对话流**（用户消息靠右、灰色背景；AI 消息靠左、白色背景；每条带时间戳）
  - 右（20%）：**设置 + 常用问题**
    - 顶部：岗位下拉 + 业务线下拉
    - 中部：常用问题下拉（**根据岗位变**，10 条 + "自定义" 选项）
    - 底部：清空当前 session 按钮
- **交互**：
  - 用户输入 → Enter 发送（Shift+Enter 换行）
  - AI 回答时显示"正在思考..."loading
  - 切换岗位下拉 → 清空右栏常用问题（因为变了）→ 但**保留**历史聊天
  - 切换业务线 → 仅影响**下一条**问题（不重置历史）
  - 常用问题选中 → 自动填入输入框 + 触发发送

### 4.2 新增

- `public/css/chat.css` —— 聊天 UI 样式（聊天气泡、滚动、loading）

### 4.3 不改

- `public/index.html`（登录页）
- `public/dashboard.html`（仪表盘，仍可点进 workspace）
- 其他页面（admin/review/knowledge）

## 6. 关键风险

1. **qa-history 文件增长**：高频使用会膨胀。**对策**：超过 1000 条 trim 旧的；按月归档 `data/qa-history-2026-08.json`
2. **频次统计冷启动**：上线首次打开下拉是空的。**对策**：预置 30 条种子
3. **动态 few-shot 性能**：qa-examples 向量化 + 每次检索 = 额外 50-100ms。**对策**：启动时预热索引，缓存到内存
4. **聊天 session 区分**：浏览器关掉重开算新 session 还是续？**对策**：用 sessionStorage 存 sessionId，关闭即失效
5. **历史回放与 RAG 数据漂移**：3 个月后回看历史，RAG 索引已变。**对策**：qa-history 已存 `ragChunks` 快照（不依赖实时索引）
