# 任务包 D：能力中心（新功能，高优先级）

## 问题描述
缺少"能力中心"功能。这是一个新的系统模块，用于配置AI助手的各种能力。

用户可以从零开始配置一个AI助手的能力，配置后AI助手就多一个能力。

## 产品设计

### 能力中心的概念
**能力中心** = 能力配置和管理的中心枢纽

### 核心功能：五大菜单

能力中心包含 5 个菜单模块，每个模块都能配置对应的能力：

#### 1. Workflow（工作流）
**说明**：一个工作流是一系列步骤的组合，用于自动化完成某项任务

**配置内容**：
- 工作流名称
- 工作流描述
- 工作流步骤（可视化编辑或代码定义）
- 工作流的输入输出定义
- 触发条件

**示例**：
- "生成PRD的工作流" - Step1：收集需求 → Step2：组织内容 → Step3：生成文档
- "代码审查工作流" - Step1：接收代码 → Step2：静态分析 → Step3：生成报告

#### 2. Skill（技能）
**说明**：一个技能是AI助手的专业能力，比如"产品经理分析技能"、"代码审查技能"

**配置内容**：
- 技能名称
- 技能描述
- 技能的Prompt（如何使用这个技能）
- 技能适用的场景
- 技能所需的Reference数据

**示例**：
- "产品经理分析技能" - 如何分析市场、竞争对手、用户需求
- "代码审查技能" - 如何审查代码质量、安全性、性能

#### 3. Reference（参考资料）
**说明**：参考资料库，AI助手在回答时可以引用这些资料

**配置内容**：
- 资料库名称
- 资料库描述
- 资料内容（知识库中的Chunk）
- 资料的标签和分类

**示例**：
- "公司产品文档库" - 产品的各个文档
- "技术规范库" - 代码规范、架构规范等
- "案例库" - 成功案例、最佳实践

#### 4. Script（脚本）
**说明**：自动化脚本，AI助手可以执行这些脚本来完成任务

**配置内容**：
- 脚本名称
- 脚本描述
- 脚本代码（JavaScript、Python等）
- 脚本的参数和返回值定义

**示例**：
- "发送邮件脚本" - 自动发送邮件
- "数据查询脚本" - 从数据库查询数据
- "文件处理脚本" - 处理和转换文件

#### 5. Tool（工具）
**说明**：外部工具集成，AI助手可以调用这些工具

**配置内容**：
- 工具名称
- 工具描述
- 工具的API接口（URL、认证信息）
- 工具的参数和响应格式定义

**示例**：
- "Jira工具" - 查询和创建任务
- "Slack工具" - 发送消息
- "数据分析工具" - 数据分析和可视化

### 使用场景

**场景1：为AI助手配置"生成PRD"能力**

步骤：
1. 打开能力中心 → Skill 菜单
2. 新建 Skill："产品规划能力"
3. 填写技能Prompt：如何收集需求、分析市场、编写PRD
4. 关联 Reference：公司产品文档库、案例库
5. 保存

结果：AI助手就多了一个"生成PRD"的能力，用户问AI："帮我生成一个PRD"，AI就能用这个能力回答

**场景2：为AI助手配置"自动发送邮件"工作流**

步骤：
1. 打开能力中心 → Workflow 菜单
2. 新建 Workflow："每日报告工作流"
3. 定义步骤：
   - Step1：收集数据（使用Script：数据查询脚本）
   - Step2：生成报告（使用Skill：报告生成技能）
   - Step3：发送邮件（使用Tool：邮件工具）
4. 设置触发条件：每天上午10点
5. 保存

结果：系统就自动配置了一个每日报告工作流，每天自动执行

## 系统架构

### 页面结构
```
能力中心
├── 左侧菜单
│   ├── Workflow
│   ├── Skill
│   ├── Reference
│   ├── Script
│   └── Tool
├── 中间列表区域
│   ├── 搜索和筛选
│   └── 能力列表（表格）
└── 右侧详情和编辑区域
    ├── 能力详情
    ├── 编辑表单
    └── 保存/删除按钮
```

### 数据库设计

需要创建以下表：

1. **capabilities** - 能力表
   - id (主键)
   - type (workflow/skill/reference/script/tool)
   - name (能力名称)
   - description (描述)
   - created_at (创建时间)
   - updated_at (更新时间)
   - created_by (创建者)
   - is_active (是否启用)

2. **capability_details** - 能力详情表
   - id (主键)
   - capability_id (关联到 capabilities)
   - content (详细内容，JSON格式)
   - version (版本号)

3. **capability_relations** - 能力关系表
   - id (主键)
   - capability_id (能力ID)
   - related_capability_id (关联的能力ID)
   - relation_type (关系类型：uses/references/includes等)

### API端点设计

```
GET /api/capability/list?type=workflow&keyword=...&page=1
POST /api/capability/create

PUT /api/capability/:id
DELETE /api/capability/:id

GET /api/workflow/list
POST /api/workflow/create
GET /api/workflow/:id/execute (执行工作流)

GET /api/skill/list
POST /api/skill/create
...

// 其他类似
```
