# 任务包 C：审核中心重新设计

## 问题描述
审核中心的设计太草率，没有基本的表格，跟市面上产品的设计逻辑完全不同。

应该做成表格列表设计：
- 一行对应一个待审文件
- 有操作栏可以选择审核操作
- 能看到最近上传的文件的审核状态
- 参考市面上的产品设计（如后台管理系统、内容管理系统）

## 新的审核中心设计

### 页面结构
```
审核中心
├── 搜索和筛选区域
│   ├── 文件名搜索
│   ├── 上传时间范围筛选
│   ├── 审核状态筛选（待审、已通过、已驳回）
│   └── 查询按钮
├── 表格列表
│   ├── 文件名
│   ├── 上传者
│   ├── 上传时间
│   ├── 文档类型
│   ├── 审核状态（待审/已通过/已驳回）
│   ├── 最后修改时间
│   └── 操作栏
└── 分页
```

### 表格列定义

| 列名 | 说明 | 类型 |
|------|------|------|
| 文件名 | 上传的文档名称 | 文本 |
| 上传者 | 上传文件的用户 | 文本 |
| 上传时间 | 文件上传的时间 | 日期时间 |
| 文档类型 | PDF/Word/TXT等 | 标签 |
| 文件大小 | 文档大小 | 文本 |
| 审核状态 | 待审/已通过/已驳回 | 状态标签 |
| 驳回原因 | 如果是驳回，显示原因 | 文本（可选） |
| 操作 | 查看、审核、下载 | 操作按钮组 |

### 操作栏功能

| 操作 | 说明 |
|------|------|
| 查看预览 | 预览文档内容 |
| 审核通过 | 标记为已通过 |
| 审核驳回 | 驳回并填写原因 |
| 下载 | 下载原始文件 |
| 删除 | 删除待审文件 |

## 修复步骤

### 前端部分
1. **找到审核中心页面** - `public/` 中的位置
2. **重新设计HTML结构**
   - 创建搜索和筛选区域
   - 创建表格（使用表格库，如 DataTables 或自制）
   - 创建分页
3. **添加样式**
   - 响应式设计
   - 状态标签的颜色区分（待审=黄色、已通过=绿色、已驳回=红色）
   - 操作按钮的样式

### 后端部分
1. **检查审核API** - `routes/` 中的审核相关接口
2. **确保API能够返回**
   - 待审文件列表
   - 搜索和筛选功能
   - 分页信息
3. **添加必要的API端点**（如果缺失）
   - GET /api/audit/list - 获取待审文件列表
   - POST /api/audit/approve - 审核通过
   - POST /api/audit/reject - 审核驳回
   - 其他必要的操作
