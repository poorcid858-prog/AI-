# 任务包 M5：知识中心前端 — 四层列表页 + 操作栏

> 对应 PM 问题：**问题3（知识中心重建）— 第三阶段：前端页面**

---

## 1. 任务描述

基于 M3/M4 的后端 API，重建知识中心前端页面。覆盖四个独立列表页面：原始文档、标准化文档、Chunk、向量化数据。**依赖 M3（数据模型）+ M4（处理引擎/API）。**

## 2. 需求要点（引用需求文档）

### 2.1 四层独立列表（需求第5、27、28、29节）
- **原始文档**：列表（只展示当前最新版本对应的文档主记录，按上传时间从近到远排序）、上传按钮
- **标准化文档**：列表（标准化文档ID、原始文档ID可点击跳转、文档名称、版本号、处理状态、创建时间）
- **Chunk**：列表（Chunk ID、标准化文档ID可点击跳转、版本号、Chunk序号、标题、内容摘要、标签、状态）
- **向量化数据**：列表（Vector ID、Chunk ID可点击跳转、版本号、Embedding模型、向量维度、状态）

### 2.2 原始文档操作栏（需求第9节）
按钮必须根据当前状态动态展示：
- 预览
- 生成向量数据（审核通过且未处理时显示）
- 删除（向量化前允许，向量化后不允许）
- 发布新版本（已形成正式版本的文档）
- 上线/下线
- 重新发起审核（审核失败后显示）

### 2.3 审核状态流转（需求第8节）
- 上传后：待审核、未处理、未生效
- 审核通过：显示"生成向量数据"
- 审核失败：显示"重新发起审核"

### 2.4 删除规则（需求第20节）
- 未完成向量化处理 → 允许删除
- 已完成向量化 → 不允许删除，只能下线

### 2.5 历史版本（需求第23节）
- 原始文档详情页展示所有历史版本
- 历史版本全部保留，不得物理删除

### 2.6 "生成向量数据"入口（需求第11节）
- 页面不存在"标准化处理"按钮，只有"生成向量数据"一个触发入口

### 2.7 批量操作（需求第19、25节）
- 批量生成向量数据
- 批量上线/下线

## 3. 修改清单

### 3.1 重写 `public/knowledge.html`
- 四个独立列表页（Tab 切换）：原始文档 / 标准化文档 / Chunk / 向量化数据
- **原始文档 Tab**：
  - 列表：标题、上传时间、审核状态、处理状态、生效状态、操作按钮
  - 上传表单（文件选择 + 标题 + 业务线/安全分级 + 标签）
  - 操作栏：预览/生成向量数据/删除/发布新版本/上线/下线/重新发起审核（按状态动态显示）
  - 批量选择：checkbox，批量生成向量/批量上下线
- **标准化文档 Tab**：列表 + 原始文档ID可点击跳转
- **Chunk Tab**：列表 + 标准化文档ID可点击跳转
- **向量化数据 Tab**：列表 + Chunk ID可点击跳转 + 技术信息
- 页面套用 K1 侧边栏：`App.renderSidebar('knowledge', 'kb')`

### 3.2 重写 `public/js/knowledge.js`
- 数据加载：从新 API（M4 的 `/api/knowledge/*` 端点）拉取数据
- 渲染逻辑：四层列表渲染
- 操作逻辑：生成向量/删除/上下线/发布新版本/重新审核 按钮
- 批量操作：checkbox 选择 + 批量执行
- 异步进度：调用 `/api/knowledge/tasks/:taskId` 轮询展示进度条
- 血缘跳转：点击父级 ID 跳转到对应父级详情
- 上传逻辑：文件读取 + 调用上传 API

### 3.3 重写 `public/css/knowledge.css`
- 四层 Tab 样式
- 操作按钮样式（按状态动态显示）
- 进度条样式
- 表格样式

### 3.4 新增 API 端点（如果 M3/M4 未全部提供）
- 确认 M3/M4 提供以下端点齐全：
  - GET /api/knowledge/documents（原始文档列表）
  - GET /api/knowledge/standardized（标准化文档列表）
  - GET /api/knowledge/chunks（Chunk 列表）
  - GET /api/knowledge/vectors（向量化数据列表）
  - POST /api/knowledge/upload（上传）
  - POST /api/knowledge/:versionId/generate-vectors（生成向量）
  - GET /api/knowledge/:versionId（版本详情）
  - POST /api/knowledge/:versionId/re-review（重新发起审核）
  - POST /api/knowledge/:versionId/online / offline（上下线）
  - POST /api/knowledge/:documentId/new-version（发布新版本）
  - DELETE /api/knowledge/:versionId（删除）
  - POST /api/knowledge/batch-generate / batch-online / batch-offline（批量操作）
