# 差距分析与重构方案（V2.0 需求对标）

> 本文档是**项目重构的总纲**。基于《主人的需求文档》V2.0 与代码审计，输出差距清单 + 任务包拆解 + 并行分配方案。
> **任何新 session 开工前必须先读本文档**，认领自己的任务包后执行。

---

## 一、核心结论（一句话）

项目代码量与需求体量基本匹配，**但核心链路断了**。知识中心、运营中心、系统配置等"外围模块"做得扎实，但最核心的 **AI 工作台完整链路是假的**：Workflow 引擎不存在、意图识别不存在、RAG 检索结果没有真正进入 Prompt、能力中心没有聚合视图。重构的核心是**把主线接起来**，而不是推倒重来。

---

## 二、技术栈与数据层现状

- **后端**：Node.js + Express + JSON 文件存储（`lib/store.js` 封装读写）
- **检索**：TF-IDF 向量 + 余弦相似度（模拟 Embedding，`lib/vector-store.js`）
- **前端**：Bootstrap 5.3 深色主题（`custom-theme.css`）+ 已集成 19 个第三方插件（见 `docs/前端插件清单.md`）
- **测试**：33 个测试文件 / 526 用例
- **五大核心能力缺失或空壳**：
  1. **Workflow 引擎** —— `routes/workflow.js` 仅占位 health
  2. **意图识别 → Workflow 路由** —— `POST /chat/send` 直接返回模拟字符串
  3. **RAG 结果未进入 Prompt** —— 检索结果只存快照，不传 Prompt
  4. **能力聚合视图** —— 只有 5 种孤立类型列表
  5. **完整链路已断** —— 我告诉你，链路断在"意图识别→Workflow"

## 五、并行 session 分配方案

### 推荐：4 个 session 并行（平衡依赖与速度）

| Session | 认领任务包 | 顺序 | 文件可并行性 |
|---------|-----------|------|-------------|
| **Session 1（核心链路）** | 1️⃣ Workflow 引擎 → 2️⃣ 完整 AI 链路 → 9️⃣ 链路记录+双向反馈 | 必须严格按序（2 依赖 1，9 依赖 2） | 独享 `lib/workflow-engine.js`、`routes/workflow.js`、`routes/chat.js`、`lib/retrieval-snapshot.js` |

| **Session 3（功能补全）** | 5️⃣ 系统管理补全 → 6️⃣ 知识中心增强 → 8️⃣ 客服分支增强 | 相互独立可并行 | 独享 `lib/admin-config.js`、`public/admin-config.html`、`public/knowledge.html`、`routes/service-admin.js` |
| **Session 4（运营+前端优化）** | 7️⃣ 运营中心增强 → 🔟 前端全面重构+统一 → 1️⃣3️⃣ 插件落地 | 10/13 可并行 | 独享 `public/operations.html`、`public/js/app.js`、各 `public/*.html` 样式统一 |

> **⚠️ 关键约束**：
> - 任务包 1️⃣ 和 2️⃣ 是**主线核心**，Session 1 必须先完成，Session 2/3/4 的 3️⃣/7️⃣/9️⃣ 才可开动（7 依赖 2，9 依赖 2）。

> - 所有 session 各自独享自己的文件，不交叉修改。
