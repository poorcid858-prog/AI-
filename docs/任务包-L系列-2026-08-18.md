## 二、现状诊断

### 问题 1：AI 工作台二级菜单
- 当前 `sidebar.js` 中 `workbench` 有 5 个子项：产品助手/测试助手/前端助手/AI对话/历史记录
- `workspace.html` 不读取 `?role=` 参数来切换角色，所以点"产品助手"等链接后打开的是同一个页面，角色未切换，功能无效
- **修复方案**：去掉 AI 工作台二级菜单，改为：点击一级菜单直接进入 AI 对话页面，或进入一个入口页（含角色选择卡片）

### 问题 2：能力中心/审核中心白屏
- 能力中心（`capability.html`）：页面加载后调用 `GET /api/capabilities`，若数据为空（`data/` 下无数据或 JSON 解析失败），列表为空显示"暂无数据"，看起来像白屏
- 审核中心（`review.html`）：能力审核 Tab 的 `GET /api/capabilities/pending-review` 路由被 `/:id` 路由拦截（`/:id` 注册在 `/pending-review` 之前，Express 参数匹配优先级高），导致返回 404
- **修复方案**：修复路由顺序（把 `/pending-review` 移到 `/:id` 之前）；确保能力中心有种子数据或空态提示更友好

### 问题 3：知识中心重建（核心工作量）
当前知识中心代码（`lib/knowledge-layers.js`、`routes/knowledge.js`、`public/knowledge.html`、`public/js/knowledge.js`）与《知识中心需求说明书》差距巨大：
- 无 Document + DocumentVersion 拆分模型，只有扁平的四层 JSON
- 无"审核状态/处理状态/生效状态"三状态模型
- 无"生成向量数据"一键触发链路机制
- 无异步处理进度与失败重试
- 无版本管理与历史版本保留
- 无血缘追溯（父级 ID 可点击跳转）
- 无批量上下线、批量生成向量数据
- 元数据 AI 识别 + 人工修改流程未实现
- 标准化文档/Chunk/向量化数据三个页面需要重建

### 问题 4：菜单 href 跳转错位
- 自查发现 `sidebar.js` 中 `operations` 模块下的 `history` 子项 href 指向 `/operations.html`，但 PM 说"历史记录"应属于 AI 工作台而非运营中心——这可能是 PM 指的跳转错位
- 其他可能：`Chunk 管理` 指向 `/knowledge.html?tab=chunks` 但 `knowledge.html` 可能无 `tab=chunks` 处理逻辑（需确认）

### 任务包 L3：知识中心数据层 + 处理链路重建（核心）

**这是本批次最大任务包**。严格按《知识中心需求说明书》重建知识中心后端。

**数据模型（按需求文档第31节的实体模型）**：
新建/重写以下数据层，全部用 JSON 文件存储（与现有 `lib/store.js` 兼容）：

- **Document**：`document_id`、`document_name`、`current_version_id`、`created_at`、`updated_at`
- **DocumentVersion**：`version_id`、`document_id`、`version_number`（仅成功完成向量化后才赋值）、`source_file_id`、`review_status`（待审核/通过/失败）、`processing_status`（未处理/处理中/成功/失败）、`online_status`（未生效/已上线/已下线）、`metadata`（AI识别的元数据JSON）、`created_at`、`updated_at`
- **StandardizedDocument**：`standardized_document_id`、`document_id`、`version_id`、`content`（标准化后文本）、`processing_status`、`created_at`、`updated_at`
- **Chunk**：`chunk_id`、`standardized_document_id`、`document_id`、`version_id`、`chunk_index`、`title`（按标题切分时提取）、`content`、`metadata`（继承原始文档元数据 + AI识别标签）、`processing_status`、`created_at`、`updated_at`
- **Vector**：`vector_id`、`chunk_id`、`document_id`、`version_id`、`embedding_model`、`dimension`、`vector`（TF-IDF 模拟向量）、`status`、`created_at`、`updated_at`

**核心 API 路由（`routes/knowledge.js` 重写）**：
1. `POST /api/knowledge/upload` — 上传文档（接受文件，创建 Document + DocumentVersion 记录，审核状态=待审核，处理状态=未处理，生效状态=未生效，第一阶段 AI 元数据识别）
2. `GET /api/knowledge/documents` — 原始文档列表（只展示最新文档记录，按上传时间排序）
3. `GET /api/knowledge/documents/:id` — 原始文档详情（含所有历史版本）
4. `GET /api/knowledge/standardized` — 标准化文档列表
5. `GET /api/knowledge/chunks` — Chunk 列表
6. `GET /api/knowledge/vectors` — 向量化数据列表
7. `POST /api/knowledge/:versionId/generate-vectors` — 【核心】生成向量数据（一键触发：标准化→按标题切Chunk→Chunk元数据AI识别→向量化，全部异步执行，返回 taskId）
8. `GET /api/knowledge/tasks/:taskId` — 查询异步处理进度（当前阶段/成功/失败/原因）
9. `POST /api/knowledge/:versionId/retry` — 从失败阶段重新处理
10. `POST /api/knowledge/batch-generate` — 批量生成向量数据
11. `POST /api/knowledge/:versionId/review` — 审核通过/驳回
12. `POST /api/knowledge/:versionId/re-review` — 重新发起审核
13. `POST /api/knowledge/:versionId/online` — 上线
14. `POST /api/knowledge/:versionId/offline` — 下线
15. `POST /api/knowledge/:versionId/batch-online` — 批量上线
16. `POST /api/knowledge/:versionId/batch-offline` — 批量下线
17. `DELETE /api/knowledge/:versionId` — 删除（仅允许未完成向量化的版本）
18. `POST /api/knowledge/:documentId/new-version` — 发布新版本
19. `GET /api/knowledge/trace/:chunkId` — 血缘追溯（从 Chunk 回溯到标准化文档→版本→原始文档→文件）

**关键处理链路（`lib/knowledge-layers.js` 重写）**：
- `generateVectors(versionId)` — 异步执行：标准化处理 → 按标题切 Chunk → Chunk 元数据 AI 识别 → 继承原始文档元数据 → Embedding 生成 Vector
- 每个阶段独立状态记录，支持失败从失败阶段重试
- 标准化处理：文本清洗、结构标准化、表格处理（表格随所属标题）
- Chunk 切分：只按标题层级切分，一个 Chunk 对应一个完整标题章节，不跨章节
- Chunk 元数据 AI 识别：语义判断业务标签（多值），继承原始文档元数据
- 向量化：1 Chunk : 1 Vector，TF-IDF 模拟 Embedding

**删除/版本规则**：
- 未完成向量化 → 允许删除
- 已完成向量化 → 不允许删除，只能下线
- 新版本发布 → 旧版本继续生效，新版本处理成功后才替换
- 历史版本全部保留，在原始文档详情页展示

**涉及文件**：
- `lib/knowledge-layers.js`（重写）
- `lib/documents.js`（重写）
- `routes/knowledge.js`（重写）
- `routes/documents.js`（重写或删除）
- `lib/vector-store.js`（微调）
- `lib/rag-engine.js`（微调，适配新数据模型）
- `lib/store.js`（可能微调，添加新数据集合）
- `lib/prompt-templates.js`（不需改动）

**依赖**：无（可独立于 L1/L2 并行开发）
**工作量**：8-10h｜难度：高
