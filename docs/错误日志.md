# 项目错误日志 & 复盘

## 错误 #1：聊天工作台按钮消失问题（2026-08-13）

### 问题描述
用户报告在聊天工作台页面看不到"+ 新会话"、"发送"、"清空会话"等按钮。

### 根本原因分析

**错误修改**：在 `public/css/style.css` 中添加了全局的 `overflow: hidden` 到 body 元素：
```css
body {
  height: 100%;
  overflow: hidden;  // ❌ 这是问题所在
}
```

**为什么会导致按钮消失**：
1. `overflow: hidden` 在 body 元素上，会剪裁所有超出 body 尺寸的内容
2. 工作台布局采用 3 列网格（左 20% + 中 60% + 右 20%）
3. 当左栏的 session-list 使用 `flex: 1` 占满可用空间时，下方的按钮会被推出视口
4. body 的 `overflow: hidden` 直接剪裁了这些溢出的按钮，导致完全看不到

### 修复方案
将 `overflow: hidden` 从 body 移到 #workspace（工作台容器），这样：
- body 本身不剪裁内容
- 只有工作台内部的溢出被剪裁
- 按钮可以在布局调整后正常显示

### 教训
- **全局 CSS 修改风险高**：`overflow: hidden` 不应该全局应用到 body，应该只在需要剪裁的具体容器上应用
- **没有考虑副作用**：修改 body 的 overflow 会影响整个页面的所有元素
- **应该逐步测试**：修改后应该立即在浏览器中验证所有界面元素是否正常显示

## 错误 #2：按钮需要滚动才能看到（2026-08-13）

### 问题描述
虽然按钮代码存在且不被隐藏，但用户仍需要向下滚动才能看到按钮。这违背了 PM 的需求："**整个页面不用滚动条，并且能看到全部要素**"。

### 根本原因
1. 左栏的 `.session-list` 设置了 `flex: 1`，会尽可能扩展占据可用空间
2. 当历史记录较多时，session-list 会将下方的"+ 新会话"按钮挤出视口
3. 类似地，中栏的输入框下方的"发送"按钮也可能被 messages-container 挤压

### 待修复
需要调整布局，确保：
- 按钮总是在各栏底部可见（不被内容挤出）
- 可滚动的部分只有 session-list 和 messages-container
- 按钮区域固定在底部不参与flex伸缩
