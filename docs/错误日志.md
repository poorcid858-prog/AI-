# 项目错误日志 & 复盘

## 错误 #1：聊天工作台按钮消失问题（2026-08-13）

### 问题描述
用户报告在聊天工作台页面看不到"+ 新会话"、"发送"、"清空会话"等按钮。

### 根本原因分析

**错误修改**：在 `public/css/style.css` 中添加了全局的 `overflow: hidden` 到 body 元素：
```css
body {
  height: 100%;
  overflow: hidden;  // ❌ 这是问题所在
}
```

**为什么会导致按钮消失**：
1. `overflow: hidden` 在 body 元素上，会剪裁所有超出 body 尺寸的内容
2. 工作台布局采用 3 列网格（左 20% + 中 60% + 右 20%）
3. 当左栏的 session-list 使用 `flex: 1` 占满可用空间时，下方的按钮会被推出视口
4. body 的 `overflow: hidden` 直接剪裁了这些溢出的按钮，导致完全看不到

### 修复方案
将 `overflow: hidden` 从 body 移到 #workspace（工作台容器），这样：
- body 本身不剪裁内容
- 只有工作台内部的溢出被剪裁
- 按钮可以在布局调整后正常显示

### 教训
- **全局 CSS 修改风险高**：`overflow: hidden` 不应该全局应用到 body，应该只在需要剪裁的具体容器上应用
- **没有考虑副作用**：修改 body 的 overflow 会影响整个页面的所有元素
- **应该逐步测试**：修改后应该立即在浏览器中验证所有界面元素是否正常显示

## 错误 #2：按钮需要滚动才能看到（2026-08-13）

### 问题描述
虽然按钮代码存在且不被隐藏，但用户仍需要向下滚动才能看到按钮。这违背了 PM 的需求："**整个页面不用滚动条，并且能看到全部要素**"。

### 根本原因
1. 左栏的 `.session-list` 设置了 `flex: 1`，会尽可能扩展占据可用空间
2. 当历史记录较多时，session-list 会将下方的"+ 新会话"按钮挤出视口
3. 类似地，中栏的输入框下方的"发送"按钮也可能被 messages-container 挤压

### 修复方案（最终）

**步骤 1**：为 flex 容器添加 flex-shrink: 0
```css
.btn-block { flex-shrink: 0; }
.input-area { flex-shrink: 0; }
#clearSessionBtn { flex-shrink: 0; }
```

**步骤 2**：为伸缩项添加 min-height: 0（Flexbox 溢出控制）
```css
.session-list { min-height: 0; }
.messages-container { min-height: 0; }
```

**步骤 3**：关键修复 - 防止页面级滚动
```css
body {
  height: 100%;
  overflow: hidden;  // ✅ 这次是对的：body 100% 高度 + overflow hidden
}
```

**为什么前面的修复不够**：
- flex-shrink: 0 和 min-height: 0 只控制三栏内部的伸缩
- 但如果页面本身有 overflow，整个工作台会被挤出视口
- 必须在 body 级别阻止页面滚动

**为什么这次 body overflow: hidden 是对的**（不像错误 #1）：
- 错误 #1：body overflow: hidden 但没有同时设置高度约束，导致内容溢出无法显示
- 这次：html { height: 100% } + body { height: 100%; overflow: hidden } 一起使用
- 确保整个页面被锁定在视口内，三栏各自内滚

### ❌ 第一次修复的问题（2026-08-13 第二轮）
**添加 body overflow: hidden 后**：
- ✅ 页面不再有滚动条
- ❌ 但按钮又消失了（被 overflow: hidden 剪裁）

**原因分析**：
- body { height: 100%; overflow: hidden } 会剪裁所有超出 body 高度的内容
- 虽然按钮的 flex-shrink: 0 保护它们不被伸缩挤压
- 但整个按钮元素仍然被 overflow: hidden 剪裁，直接看不见

**教训**：
- ❌ 不能用 overflow: hidden 来隐藏滚动条（会剪裁内容）
- ✅ 应该用 Flex 布局来确保内容恰好适应，自然不会产生滚动条

### ✅ 最终解决方案（兼容两者）
```css
html { height: 100%; }

body {
  height: 100%;
  display: flex;          /* ← 关键：body 变成 flex 容器 */
  flex-direction: column;
}

#workspace {
  flex: 1;                /* ← 占满所有可用空间 */
  min-height: 0;          /* ← 允许内部伸缩 */
}
```

**为什么这样做**：
1. body 是 flex 容器，高度 100% —— 确保 body 内容不会超出视口
2. #workspace 是 flex: 1 —— 占满 body 的所有可用空间
3. 三栏各自有 overflow-y: auto 或 flex-shrink: 0 —— 内部内容自己处理滚动
4. **结果**：页面本身没有滚动条，按钮在各栏内部正常显示

### ✅ 最终验收标准
- [ ] 整个页面不需要向下滚动
- [ ] "+ 新会话"按钮始终可见于左栏底部
- [ ] "发送"按钮始终可见于中栏底部
- [ ] "清空会话"按钮始终可见于右栏底部
- [ ] session-list、messages-container、settings 各自可以内部滚动

## 元错误 #1：未遵循工作启动清单（2026-08-13）

### 问题描述
如果发现我在开始任务时**没有调用 superpowers skill**，或在进展.md 中**缺少 superpowers 记录**。

### 根本原因
- 我读了 MEMORY.md 但没有真正执行工作启动清单
- 或者记得要用但"忘记了"在实际开始前调用

### 预防机制
1. **MEMORY.md 置顶** → work-initialization-checklist 必须被看到
2. **进展.md 验证** → 每条记录必须包含使用的 superpowers skill
3. **纠错协议检查** → 下次问题会追踪到"流程违规"
4. **用户可见** → 进展.md 中缺少 skill 记录，用户一眼看穿

### 不可接受的理由
- "我忘记了" → 不接受，因为 MEMORY.md 会在每个 session 提醒
- "任务太简单" → 不接受，所有"有实质产出"的任务都要遵循
- "下次一定" → 不接受，这次没做就已经违规了
