## ⚠️ 强制规则：每个 session 必须遵守

### 规则 1：必须使用 superpowers 插件

**这不是建议，是铁律。** 原因：
- 用户（PM）已明确要求每个 session 都要用
- 不用的后果：被记录到 `docs/错误日志.md` 为 PROCESS_VIOLATION
- 用户通过检查 `进展.md` 中是否有「使用 superpowers skill」字段来验证

**执行方式**：每次开始有实质产出的任务前，先调用 Skill 工具，选择对应的 superpowers skill：
- 编码实现 → `superpowers:test-driven-development`
- 问题排查 → `superpowers:systematic-debugging`
- 并行任务 → `superpowers:dispatching-parallel-agents`
- 设计/计划 → `superpowers:writing-plans`
- 完成前 → `superpowers:verification-before-completion`

### 规则 2：文件所有权

| 文件 | 谁可以改 |
|------|---------|
| 自己的任务包文件 | 自己 |
| 别人的任务包文件 | ❌ 不能碰 |
| `server.js` 路由注册行 | 任务包 C 可追加；只加不删，改动后立即在进展.md 记录 |
| 其他共享代码 | 任务包文档明确写明的那个 session 才能改 |
| `进展.md` | 所有 session 可写，但**必须先 Read 最新状态再 Edit**，加 `[任务包名称]` 前缀 |
| `docs/并行任务入口.md` | 任务完成后更新自己的状态行 |

**进展.md 并发写入规则**：
1. Edit 前必须 Read 最新版（工具强制，防止基于旧状态覆盖）
2. 若 Read 时发现别人的新记录，在其**上方**插入自己的记录
3. 若 Edit 因文件已变而失败 → **重读重写**，不要重试旧内容
4. 每条记录格式：`[任务包X] 内容`

### 规则 3：进展记录格式

每条记录格式：
```
[任务包名称] 做了什么
- 使用 superpowers skill：superpowers:xxx
- 完成情况
- ⚠️ 待决定（如果有）
```

## 项目一句话

把企业散落的 Word/PDF/PPT 知识加工成 AI 可引用的知识库，为产品/测试/前端/客服四类角色生成文档。技术栈：Node.js + Express + JSON 文件存储 + 内存 TF-IDF 语义检索。
