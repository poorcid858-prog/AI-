# 任务包 M4：知识中心后端重构 — 异步处理引擎 + 处理链路

> 对应 PM 问题：**问题3（知识中心重建）— 第二阶段：处理链路**

---

## 1. 任务描述

为知识中心实现异步处理引擎，覆盖"生成向量数据"一键触发链路（标准化→按标题切Chunk→元数据识别→向量化）、处理进度展示、失败重试、批量处理。**依赖 M3 的数据模型。**

## 2. 需求要点（引用需求文档）

### 2.1 "生成向量数据"是唯一入口（需求第11节）
- 原始文档页面只有"生成向量数据"按钮
- 点击后自动执行：原始文档 → 标准化 → Chunk切分 → Chunk元数据AI识别 → 向量化
- 用户不能单独触发中间步骤
- 前置条件：审核状态 = 审核通过，且当前版本尚未完成知识处理

### 2.2 异步处理与进度（需求第17节）
- 点击后后台异步执行，不阻塞页面
- 必须展示：总体处理状态、当前处理阶段、处理进度、失败阶段、失败原因

### 2.3 失败重试（需求第18节）
- 每个处理阶段有独立状态
- 从失败阶段继续，已成功且有效的上游阶段无需重复执行

### 2.4 批量生成（需求第19节）
- 支持批量选择审核通过的文档
- 每个文档独立处理，一个失败不影响其他

### 2.5 Chunk 只按标题切分（需求第13节）
- 以标题层级作为主要切分依据
- 一个 Chunk 对应一个完整标题章节
- 不允许跨章节切分
- 标题及其内容属于同一个 Chunk
- 表格跟随所属标题进入该 Chunk

### 2.6 自动化标准化（需求第12节）
- 文本清洗、文档结构标准化、表格处理（表格保持结构化格式）、图片/OCR、基础文档信息

## 3. 修改清单

### 3.1 新建异步处理引擎 `lib/async-processor.js`
- 任务模型：`task_id, versionId, status(queued/running/success/failed), phases[], currentPhase, progress, error`
- 阶段定义：标准化(standardize) → 切Chunk(chunking) → 元数据识别(meta_recognize) → 向量化(embedding)
- 每个阶段独立状态，支持从失败阶段重试
- 存储：用 JSON 文件（`data/processing-tasks.json`），配 `store.js`
- 非阻塞：默认用 setTimeout 模拟异步，其实 sync 执行但响应立即返回 taskId；或用真实的异步任务

### 3.2 新建路由 `routes/processing.js`
- `POST /api/knowledge/:versionId/generate-vectors` — 触发生成向量（返回 taskId）
- `GET /api/knowledge/tasks/:taskId` — 查询任务进度
- `POST /api/knowledge/tasks/:taskId/retry` — 从失败阶段重试
- `POST /api/knowledge/batch-generate` — 批量触发
- `GET /api/knowledge/tasks/list` — 任务列表

### 3.3 修改 `lib/document-processor.js` — Chunk 按标题切分
- 改写 `splitToChunks` 函数：以 Markdown 标题（#/##/###）作为切分点
- 一个 Chunk = 一个完整标题章节（标题 + 内容）
- 表格跟随所属标题进入对应 Chunk
- 不跨章节切分
- 返回 Chunk 数组含 `heading` 标题字段

### 3.4 修改 `lib/knowledge-layers.js` — 补充处理链路函数
- `generateVectors(versionId)` 整合：标准化→切Chunk→元数据→向量化
- `getProcessingStatus(versionId)` 返回当前处理状态
- `retryFromPhase(versionId, phase)` 从失败阶段重试

### 3.5 注册路由
- 在 `server.js` routeModules 中追加 `['/api/processing', './routes/processing']`
