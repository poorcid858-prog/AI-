# 退款业务规则文档

> 本文档定义云集商城全部退款场景的判定规则、审核策略与金额计算口径，是交易线退款服务的唯一业务口径来源。对外话术请见客服知识库《退换货政策》，本文档含内部审核阈值，**不可对外披露**。

## 1. 退款类型

| 类型码 | 类型名 | 适用场景 | 是否需退回商品 | 是否影响库存 |
|---|---|---|---|---|
| REFUND_ONLY | 仅退款 | 未发货、缺货、错发漏发、商品已丢件 | 否 | 未发货则释放预占；已发货不回库 |
| RETURN_REFUND | 退货退款 | 已签收，商品完好或存在质量问题 | 是 | 质检通过后回库上架 |
| EXCHANGE | 换货 | 尺码不合、颜色不符、非质量瑕疵 | 是 | 旧品回库 + 新品出库，不产生资金流 |

### 1.1 类型选择约束

1. 订单状态为 **待付款(10)** 时不允许申请退款，只能取消订单。
2. 订单状态为 **已付款(20)/待发货(30)** 时只允许"仅退款"。
3. 订单状态为 **已发货(40)** 且未签收时只允许"仅退款"（走物流拦截退回），不允许退货退款。
4. 订单状态为 **已完成(50)** 且在售后期内时，三种类型均可申请。
5. 换货每笔订单明细行**最多申请 1 次**，换货后不可再次换货，只能退货退款。

## 2. 退款申请条件

### 2.1 时效限制

| 商品类型 | 申请时效 | 时效基准 |
|---|---|---|
| 普通实物商品 | 签收后 7 个自然日内 | `receive_time` |
| 家电大件（3C 类目） | 签收后 15 个自然日内 | `receive_time` |
| 质量问题（有质检报告） | 签收后 90 日内 | `receive_time` |
| 虚拟商品（充值卡券） | 未核销可退，已核销不可退 | 核销状态 |
| 未发货订单 | 支付后至发货前任意时间 | — |

### 2.2 硬性拦截条件

以下情况系统直接拦截，不生成退款单：

| 拦截码 | 拦截原因 |
|---|---|
| RF_ORDER_STATUS_INVALID | 订单状态不允许申请退款（如待付款、已取消、已退款） |
| RF_TIMEOUT | 超过售后申请时效 |
| RF_DUPLICATE | 同一订单明细行已存在处理中的退款单 |
| RF_AMOUNT_EXCEED | 申请金额大于该明细行可退金额（`item_pay_amount - 已退金额`） |
| RF_CATEGORY_FORBID | 类目不支持无理由退货（定制类、生鲜、贴身衣物、药品） |
| RF_RISK_BLACKLIST | 用户命中退款风控黑名单（近 90 天退款率 >70% 且退款单量 ≥10） |

## 3. 退款审核流程

### 3.1 流程节点

```
买家发起申请
  → 系统规则校验（2.2 硬性拦截）
  → 自动审核判定（3.2）
      ├─ 命中自动通过 → 直接进入退款执行
      └─ 命中人工审核 → 客服工单池
            → 客服/商家审核（24h 内）
                ├─ 通过 → 退款执行
                └─ 拒绝 → 通知买家，可申诉 1 次，申诉升级至售后主管
  → 退款执行（调用支付网关退款）
  → 到账确认（渠道回调）
```

### 3.2 自动审核通过规则

**同时满足**以下全部条件时自动通过，无需人工介入：

1. 退款类型为"仅退款"且订单未发货；
2. 申请退款金额 ≤ **500 元**；
3. 用户近 90 天退款单数 ≤ 3 笔，且退款率 ≤ 30%；
4. 该订单未使用过"退款免审"特权额度以外的组合支付；
5. 用户账号非新注册（注册 ≥7 天）且非风控灰名单。

### 3.3 人工审核触发条件

| 触发条件 | 审核方 | 时限 |
|---|---|---|
| 单笔退款金额 > 500 元 | 客服一线 | 24 小时 |
| 单笔退款金额 > 5000 元 | 售后主管二级复核 | 48 小时 |
| 退款类型为退货退款或换货 | 商家 + 仓库质检 | 商家 24 小时 + 质检 48 小时 |
| 用户近 30 天退款单数 ≥ 5 笔 | 风控 + 客服 | 48 小时 |
| 申请原因为"商品质量问题"且要求赔付 | 客服 + 品控 | 72 小时 |
| 已发货订单申请仅退款（需物流拦截） | 客服 + 物流协调 | 24 小时 |
| 订单使用了组合支付且含余额支付 | 财务侧规则复核（自动化+人工抽检 10%） | 24 小时 |

### 3.4 超时自动处理

1. 商家在退款申请后 **24 小时**未处理，系统自动同意退款（平台规则兜底）。
2. 退货退款场景，买家在商家同意后 **7 日**内未回寄商品并填写运单号，退款单自动关闭。
3. 商家收到退货后 **5 日**内未确认收货，系统自动确认并执行退款。
4. 人工审核工单超时 4 小时未处理，升级提醒至售后主管企微群。

## 4. 退款金额计算规则

### 4.1 计算总公式

```
单明细行可退金额 = 该行实付金额 - 该行已退金额
该行实付金额 = price × qty - 该行分摊优惠金额（item_discount_amount）
退款总额 = Σ 各明细行可退金额 + 可退运费 + 赔付金额
```

### 4.2 优惠券分摊规则

| 场景 | 分摊与退回规则 |
|---|---|
| 部分退款（退部分明细行） | 优惠券金额按明细行商品金额占比分摊，只退该行分摊后的实付部分，**优惠券本身不退回** |
| 全额退款（所有明细行都退） | 退回全部实付金额；优惠券按类型判定是否返还：未过期的满减券原券退回账户，活动券/新人券不退回 |
| 满减券未达门槛（因退货导致剩余金额跌破门槛） | 已使用的优惠不追回，按分摊口径退款，差额由平台承担 |
| 折扣券 | 按折后实付金额退款，折扣不追回 |
| 运费券 | 仅当运费实际退回时，运费券失效不返还 |

**分摊计算示例**：订单商品总额 300 元，使用满 300 减 50 券，实付 250 元。
- A 商品 200 元 → 分摊优惠 `50 × 200/300 = 33.33` → 实付 166.67 元
- B 商品 100 元 → 分摊优惠 `50 × 100/300 = 16.67` → 实付 83.33 元（含尾差 0.01 调整）
- 仅退 A 商品 → 退款 **166.67 元**，优惠券不返还。

### 4.3 运费处理规则

| 场景 | 运费是否退 | 退货运费承担方 |
|---|---|---|
| 未发货全额退款 | 全额退运费 | — |
| 商品质量问题 / 错发漏发 | 全额退运费 | 商家承担退货运费（凭运单据实报销，上限 20 元） |
| 七天无理由退货（全部商品） | 全额退运费 | 买家承担退货运费 |
| 七天无理由退货（部分商品） | **不退运费** | 买家承担退货运费 |
| 因退货导致订单跌破免运费门槛 | 不追收运费 | 买家承担退货运费 |
| 已投保运费险 | 运费由保险公司赔付，平台不重复退 | 保险公司 |

### 4.4 积分与余额处理

| 项目 | 规则 |
|---|---|
| 积分抵扣部分 | 退款时按抵扣比例回退积分至账户，不折算现金；回退积分有效期继承原积分有效期 |
| 下单获得的消费积分 | 全额退款则全额扣回；部分退款按退款金额比例扣回，向下取整 |
| 积分账户余额不足扣回 | 允许积分账户为负，后续获得积分优先抵扣负值 |
| 余额支付部分 | 原路退回账户余额，实时到账 |
| 组合支付 | 按"先退第三方渠道、后退余额、最后回退积分"顺序执行，各渠道退款金额不超过原支付金额 |

### 4.5 计算校验规则

1. 单笔退款金额不得大于 `paid_amount - refunded_amount`，超出直接拒绝。
2. 所有分摊运算保留 2 位小数，采用四舍五入；尾差累加到金额最大的明细行。
3. 退款完成后校验 `refunded_amount ≤ paid_amount`，越界写差异表并告警。

## 5. 退款状态机

| 状态码 | 状态名 | 说明 |
|---|---|---|
| 100 | 待审核 | 申请已提交，等待自动或人工审核 |
| 200 | 审核通过 | 待买家回寄（退货场景）或待执行退款 |
| 210 | 待买家回寄 | 商家已同意，等待买家填写回寄运单号 |
| 220 | 待商家收货 | 买家已回寄，等待商家/仓库质检确认 |
| 300 | 退款中 | 已调用支付网关，等待渠道处理 |
| 400 | 退款成功 | 渠道回调成功，资金已退出，终态 |
| 500 | 退款失败 | 渠道退款失败，需人工介入重试 |
| 600 | 已拒绝 | 审核不通过，终态（可申诉 1 次） |
| 700 | 已关闭 | 买家撤销申请或超时未回寄，终态 |

### 5.1 流转条件

| 源状态 | 目标状态 | 触发条件 |
|---|---|---|
| 待审核(100) | 审核通过(200) | 命中自动审核通过规则，或人工审核通过 |
| 待审核(100) | 已拒绝(600) | 人工审核拒绝，需填写拒绝原因码 |
| 待审核(100) | 已关闭(700) | 买家主动撤销申请 |
| 审核通过(200) | 待买家回寄(210) | 退款类型为退货退款/换货 |
| 审核通过(200) | 退款中(300) | 退款类型为仅退款，直接执行 |
| 待买家回寄(210) | 待商家收货(220) | 买家填写回寄运单号 |
| 待买家回寄(210) | 已关闭(700) | 7 日内未回寄，超时关闭 |
| 待商家收货(220) | 退款中(300) | 商家确认收货且质检通过 |
| 待商家收货(220) | 已拒绝(600) | 质检不通过（商品损坏、非原件、缺配件），需上传质检照片 |
| 退款中(300) | 退款成功(400) | 支付渠道退款回调成功 |
| 退款中(300) | 退款失败(500) | 渠道返回失败，或 T+1 未收到回调 |
| 退款失败(500) | 退款中(300) | 人工修正后重新提交，最多重试 3 次 |

## 6. 退款到账时效

| 支付方式 | 到账时效 | 说明 |
|---|---|---|
| 账户余额 | 实时 | 退款成功即到账 |
| 微信支付 | 1-3 个工作日 | 原路退回至付款微信账户 |
| 支付宝 | 1-2 个工作日 | 原路退回至付款支付宝账户 |
| 银行卡（借记卡） | 3-7 个工作日 | 受银行清算周期影响 |
| 银行卡（信用卡） | 3-15 个工作日 | 退至信用卡额度，需看银行入账周期 |
| 组合支付 | 按各渠道分别计时 | 买家端展示"最长 7 个工作日" |

**超时兜底**：退款单进入"退款中"超过 15 个工作日仍未到账，客服可发起"垫付退款"流程，由平台先行垫付到账户余额，后续与渠道核销。

## 7. 拒绝退款的场景

| 拒绝原因码 | 场景 | 是否可申诉 |
|---|---|---|
| RJ_TIMEOUT | 超出售后申请时效 | 可申诉（需提供延误证明） |
| RJ_CATEGORY | 定制商品、生鲜、贴身衣物、已激活虚拟卡券 | 不可申诉 |
| RJ_QC_FAIL | 退回商品缺失吊牌、包装、赠品或有明显使用痕迹 | 可申诉（凭开箱视频） |
| RJ_NOT_ORIGINAL | 退回商品与原订单商品不一致（非原件、调包） | 不可申诉，转风控 |
| RJ_NO_RETURN | 商家同意后 7 日内未回寄 | 不可申诉，可重新申请 |
| RJ_RISK | 命中恶意退款风控（高频退款、职业退货团伙特征） | 可申诉，风控人工复核 |
| RJ_LOGISTICS_SIGNED | 声明未收到货但物流已本人签收且有签收影像 | 可申诉 |
| RJ_USED_DAMAGE | 买家自身使用不当造成的损坏（有质检结论） | 可申诉，需第三方检测报告 |

## 8. 对账与差异处理

1. 每日 02:00 拉取支付渠道退款对账文件，与 `t_refund_order` 逐笔核对。
2. 差异类型：**平台有渠道无**（渠道未成功，需重试）、**渠道有平台无**（渠道已退，需补状态）、**金额不一致**（挂人工）。
3. 差异笔数 >10 笔或差异金额 >1000 元触发 P2 告警，通知财务与交易值班。
4. 差异处理时限：T+1 日 18:00 前清零，未清零升级至财务经理。
