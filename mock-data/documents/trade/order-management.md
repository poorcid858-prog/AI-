# 订单管理系统 PRD

## 1. 需求背景

云集商城当前日均订单量约 12 万单，大促峰值 QPS 约 3000。原订单系统状态字段散落在 4 张表中，客服查询一笔订单需要跨系统核对，平均处理时长 6 分钟。本次重构统一订单主表与订单状态机，收敛状态流转入口，支撑多商家、多仓库拆单场景。

## 2. 业务目标

| 目标 | 当前值 | 目标值 |
|---|---|---|
| 订单状态一致性（订单表与支付表核对差异率） | 0.8% | ≤ 0.01% |
| 客服单笔订单查询耗时 | 6 分钟 | ≤ 30 秒 |
| 待付款订单自动关单准确率 | 96% | 100% |
| 拆单成功率 | 未支持 | ≥ 99.9% |
| 超卖工单量（月） | 42 单 | ≤ 2 单 |

## 3. 功能范围

**本期包含**：订单创建、订单状态机、订单拆单、订单取消、订单查询（买家端/客服端）、订单超时关单、订单与支付单对账钩子。

**本期不包含**：预售订单定金模式、跨境订单报关单、拼团订单成团逻辑（排期 v3.3）。

## 4. 订单状态机

### 4.1 状态定义

| 状态码 | 状态名 | 说明 |
|---|---|---|
| 10 | 待付款 | 订单已创建，库存已预占，等待买家支付 |
| 20 | 已付款 | 支付渠道回调成功，货款已入账，等待商家接单 |
| 30 | 待发货 | 商家已接单，仓库开始拣货打包 |
| 40 | 已发货 | 运单号已回传，物流揽收成功 |
| 50 | 已完成 | 买家确认收货，或签收后自动确认，进入售后期 |
| 60 | 已取消 | 买家主动取消或超时关单，库存已释放 |
| 70 | 退款中 | 已发起退款申请，退款单处理中 |
| 80 | 已退款 | 退款金额已到账，订单终态 |

### 4.2 流转规则

| 源状态 | 目标状态 | 触发条件 | 操作方 | 超时规则 |
|---|---|---|---|---|
| 待付款(10) | 已付款(20) | 支付渠道异步回调 `trade_status=SUCCESS` 且验签通过 | 系统 | — |
| 待付款(10) | 已取消(60) | 创建后 30 分钟未支付，定时任务扫描关单 | 系统 | 创建后 30 分钟 |
| 待付款(10) | 已取消(60) | 买家点击"取消订单" | 买家 | — |
| 已付款(20) | 待发货(30) | 商家接单，或下单后 2 小时系统自动接单 | 商家/系统 | 支付后 2 小时自动接单 |
| 已付款(20) | 退款中(70) | 买家申请"仅退款"（未发货） | 买家 | — |
| 待发货(30) | 已发货(40) | 仓库回传运单号，且物流网关确认揽收 | 商家 | 支付后 48 小时未发货触发延迟发货赔付 |
| 待发货(30) | 退款中(70) | 买家申请退款且商家同意，或系统自动同意 | 买家 | 申请后商家 24 小时未处理，系统自动同意 |
| 已发货(40) | 已完成(50) | 买家确认收货 | 买家 | 物流签收后 7 天自动确认收货 |
| 已发货(40) | 退款中(70) | 买家申请"退货退款" | 买家 | 仅签收后 7 天内可申请 |
| 已完成(50) | 退款中(70) | 售后期内申请退款（签收后 7 天内） | 买家 | 超过 7 天入口关闭 |
| 退款中(70) | 已退款(80) | 退款单状态变为"退款成功" | 系统 | 退款到账 1-7 个工作日 |
| 退款中(70) | 回退原状态 | 退款申请被拒绝或买家撤销申请 | 商家/买家 | — |

### 4.3 状态机约束

1. **单向不可逆**：已退款(80)、已取消(60) 为终态，不允许再次流转。
2. **收敛入口**：所有状态变更必须走 `OrderStateMachine.transition(orderNo, event)`，禁止业务代码直接 `UPDATE order SET status=?`。
3. **乐观锁**：状态变更 SQL 必须带上 `WHERE status = {期望源状态} AND version = {版本号}`，影响行数为 0 视为并发冲突，抛 `ORD_CONFLICT` 并重试一次。
4. **状态流水**：每次流转写一条 `order_status_log`，记录源状态、目标状态、操作人、操作时间、事件来源，客服端展示该流水。

## 6. 订单创建流程

1. **参数校验**：校验收货地址、SKU 有效性、限购规则（同一 SKU 单用户单日限购 5 件）。
2. **价格试算**：调用营销服务计算优惠，返回 `total_amount`、`discount_amount`、`freight_amount`、`pay_amount`。
3. **前端价格比对**：请求携带前端展示的 `pay_amount`，与服务端试算结果不一致则返回 `ORD_PRICE_CHANGED`，要求用户刷新确认，防止比价篡改。
4. **风控校验**：调用风控服务，命中黑名单/机器刷单返回 `ORD_RISK_REJECT`。
5. **库存预占**：调用库存服务 `reserve` 接口，以 `order_no` 作为幂等键，预占有效期 30 分钟。
6. **优惠券锁定**：锁定使用的优惠券，标记为"锁定中"，不扣减。
7. **拆单**：按第 7 节规则拆单，生成父订单 + N 个子订单。
8. **落库**：同一本地事务写入 `t_order_main`、`t_order_item`、`order_status_log`。
9. **发消息**：发送 `order.created` 消息，触发关单延迟队列（延迟 30 分钟）。

## 7. 订单拆单规则

### 7.1 拆单触发条件

| 拆单维度 | 触发条件 | 拆分结果 |
|---|---|---|
| 多商家拆单 | 购物车内商品归属 ≥2 个商家 | 每个商家一个子订单，独立发货、独立售后 |
| 多仓库拆单 | 同一商家商品分布在 ≥2 个仓库 | 每个仓库一个子订单，独立运单号 |
| 履约方式拆单 | 同时存在"仓发"与"厂直发"商品 | 按履约方式拆分 |
| 预售拆单 | 现货与预售商品混合下单 | 现货单立即履约，预售单等待到货 |

### 7.2 拆单后金额分摊

1. 父订单仅作聚合，`status` 取所有子订单的最小状态码；父订单不参与支付与退款。
2. 商品金额按明细行归属直接划入对应子订单。
3. **订单级优惠**（如全站满 300 减 50 券）按各子订单商品金额占比分摊，公式：
   `子单分摊额 = round(订单级优惠总额 × 子单商品金额 / 订单商品总额, 2)`
4. **尾差处理**：分摊产生的分位尾差累加到商品金额最大的子订单，保证各子订单分摊额之和严格等于订单级优惠总额。
5. **运费**按子订单独立计算，不做分摊；订单级免运费权益优先抵扣运费最高的子订单。
6. 支付时买家只看到父订单一个支付金额，支付成功后回调按子订单逐个更新状态。

## 8. 异常场景处理

### 8.1 支付成功但订单状态未更新

| 环节 | 处理方案 |
|---|---|
| 检测 | 每 3 分钟扫描"支付单成功但订单仍为待付款且支付时间超过 2 分钟"的记录 |
| 补偿 | 以支付单 `pay_trade_no` 为准，重放一次状态流转事件，幂等推进到已付款 |
| 兜底 | 补偿 3 次仍失败，生成人工工单推送交易值班群，客服端标记"支付异常处理中" |
| 禁止 | 严禁在此场景执行自动关单，关单任务需先校验支付单状态 |

### 8.2 库存不足

| 场景 | 处理方案 |
|---|---|
| 下单时预占失败 | 直接拦截，返回 `ORD_STOCK_LACK`，提示"商品库存不足，请调整数量" |
| 预占成功但仓库拣货缺货 | 商家发起"缺货退款"，走仅退款流程，订单流转到退款中；同时给买家发 5 元无门槛补偿券 |
| 超卖（并发预占击穿） | 库存服务侧用 Redis 原子扣减 + DB 行锁双重校验；发现超卖按下单时间先后履约，靠后订单缺货退款 |
| 关单未释放库存 | 关单成功后发 `order.canceled` 消息释放预占；消息消费失败进重试队列，最多重试 5 次后告警 |

### 8.3 其他异常

| 异常 | 处理方案 |
|---|---|
| 重复提交下单 | 前端下单令牌 + 服务端以 `user_id + 购物车指纹` 做 5 秒内幂等，返回首次订单号 |
| 支付渠道回调重复 | 以 `pay_trade_no` 做唯一索引，重复回调直接返回成功，不重复更新 |
| 收货地址下单后失效 | 未发货可修改地址一次；已发货不可修改，引导联系物流改址 |
| 拆单部分子单支付成功 | 不允许部分成功，父订单支付为一次原子操作，渠道侧只有一笔支付流水 |

## 9. 订单查询能力

### 9.1 买家端查询

| 查询维度 | 支持情况 |
|---|---|
| 按订单状态筛选 | 支持全部 8 个状态 + "全部"聚合 |
| 按时间范围 | 支持近 3 个月、近 1 年、自定义（最长跨度 1 年） |
| 关键词搜索 | 支持订单号精确匹配、商品名称模糊匹配 |
| 分页 | 每页 20 条，最大分页深度 50 页；超过引导缩小时间范围 |
| 数据时效 | 走订单查询从库 + Redis 缓存，缓存 TTL 60 秒，状态变更主动失效 |

### 9.2 客服端查询

客服端在一个页面聚合展示，避免跨系统核对：

| 展示区块 | 内容 |
|---|---|
| 订单基础信息 | 订单号、父子订单关系、买家 ID、商家、下单时间、当前状态 |
| 金额明细 | 商品总额、运费、优惠明细（逐张券 + 活动 + 积分抵扣）、应付、实付、已退 |
| 支付信息 | 支付渠道、支付流水号 `pay_trade_no`、支付时间、组合支付各渠道金额 |
| 状态流水 | `order_status_log` 全量记录，含源状态、目标状态、操作人、事件来源 |
| 物流信息 | 物流公司、运单号、物流轨迹（实时拉取物流网关） |
| 售后记录 | 关联的全部退款单及其状态流转 |
| 风控标记 | 是否命中风控、风控原因（仅客服主管可见） |

## 10. 数据一致性保障

| 保障手段 | 说明 |
|---|---|
| 本地事务 | 订单主表、明细表、状态流水在同一本地事务内写入 |
| 乐观锁 | 状态流转带 `version` 校验，冲突重试一次后失败 |
| 幂等键 | 下单用 `requestId`，支付回调用 `pay_trade_no`，库存/券操作用 `order_no` |
| 消息可靠投递 | 采用本地消息表 + 定时投递，保证订单事件不丢 |
| 消息幂等消费 | 消费端以事件 ID 去重，重复消息直接丢弃 |
| 定时补偿 | 支付状态补偿（3 分钟）、库存预占清理（5 分钟）、券锁定解锁（5 分钟） |
| 日对账 | 订单表与支付表、订单表与库存流水每日核对，差异挂工单 |

| 监控指标 | 阈值 | 告警级别 |
|---|---|---|
| 下单成功率 | <99.5% 持续 5 分钟 | P1 |
| 支付回调处理失败率 | >0.1% 持续 5 分钟 | P0 |

## 12. 与其他系统的依赖

| 依赖系统 | 交互方式 | 依赖强弱 | 降级方案 |
|---|---|---|---|
| 支付网关 | 同步接口 + 异步回调 | 强依赖 | 不可降级，支付网关不可用则下单页提示"支付服务繁忙" |
| 库存服务 | 同步接口（预占/释放） | 强依赖 | 不可降级，预占失败直接拦截下单 |
| 营销服务（优惠券/活动） | 同步接口（试算/锁定/核销） | 中依赖 | 超时降级为不使用优惠下单，并提示用户 |
| 会员服务 | 同步接口（等级/折扣/积分抵扣） | 中依赖 | 超时降级为普通会员价，积分不可用并提示 |
| 风控服务 | 同步接口 | 弱依赖 | 超时视为通过，异步补充校验 |
| 物流服务 | 异步（运单回传）+ 同步（轨迹查询） | 弱依赖 | 轨迹查询失败展示"物流信息加载失败，请稍后重试" |
| 消息中心 | 异步消息 | 弱依赖 | 失败进重试队列，不阻塞主流程 |

## 13. 验收标准

1. 8 个订单状态的 12 条流转路径全部可通过接口触发，非法流转返回 `ORD_STATUS_INVALID`。
2. 待付款订单在创建后 30 分钟（误差 ≤60 秒）自动关单，库存 100% 释放。
3. 并发 500 QPS 下单同一 SKU，不出现超卖，订单金额与支付金额差异为 0。
4. 多商家 + 多仓库混合购物车，拆单后各子订单 `pay_amount` 之和等于父订单 `pay_amount`，误差为 0 分。
5. 支付回调重复投递 10 次，订单状态只推进一次，`order_status_log` 只新增一条记录。
6. 客服端可在一个页面看到订单全量状态流水、支付流水号、物流运单号，单笔查询耗时 ≤30 秒。
