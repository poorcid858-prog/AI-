# 支付网关技术文档

## 1. 概述

支付网关（Payment Gateway，简称 PGW）是云集商城所有交易资金流的统一出入口。上游对接订单系统，下游对接微信支付、支付宝、银联、余额账户、组合支付路由，为订单系统屏蔽各渠道的差异。

## 2. 支持的支付方式

| 支付方式 | 渠道编码 | 支付类型 | 退款方式 | 结算周期 |
|---|---|---|---|---|
| 微信支付 | WECHAT | 扫码支付 / JSAPI / 小程序 / App | 原路退回 | T+1 |
| 支付宝 | ALIPAY | 网页支付 / App 支付 / 小程序 | 原路退回 | 实时 + T+1 |
| 银行卡 | BANKCARD | 快捷支付（银联/网联） | 原路退回 | T+1 至 3 个工作日 |
| 账户余额 | BALANCE | 余额支付 | 即时退回余额 | 实时 |
| 组合支付 | COMBINE | 余额 + 第三方渠道混合支付 | 分渠道退款 | 按各渠道 |

### 2.1 组合支付规则

1. 组合支付仅支持"余额 + 一种第三方渠道"的组合，**不支持**两种第三方渠道组合。
2. 余额优先使用，余额不足时差额走第三方渠道。例如：订单 100 元，余额 30 元，则余额扣 30 元，第三方渠道支付 70 元。
3. 组合支付退款的资金回退顺序：先退第三方渠道，当第三方渠道已退至原支付金额上限后，余量退至余额。
4. 组合支付下单时，前端需分开展示两种支付方式的金额，并提供统一的支付确认操作。

## 3. 支付流程时序

### 3.1 标准支付流程

```
买家前端            订单系统            支付网关           支付渠道
   |                  |                  |                  |
   |--- 1.提交订单 -->|                  |                  |
   |                  |--- 2.创建支付单 ->|                  |
   |                  |                  |--- 3.调用渠道 --->|
   |<-- 4.返回支付参数-|                  |<- 渠道返回参数 ---|
   |--- 5.前端调起支付-|                  |                  |
   |    (扫码/跳转/弹窗)                   |                  |
   |<- 6.用户完成支付-|                  |                  |
   |                  |                  |<-- 7.异步回调 ----|
   |                  |                  |                  |
   |                  |<-- 8.通知订单 ---|                  |
   |                  |    (transaction.updated)            |
   |--- 9.轮询/长连接->|                  |                  |
   |<-- 10.返回最新状态-|                  |                  |
```

### 3.2 流程说明

| 步骤 | 操作 | 说明 |
|---|---|---|
| 1 | 买家提交订单 | 携带前端识别的 `pay_amount` 用于价格比对 |
| 2 | 创建支付单 | 生成 `pay_order_no`，记录渠道、金额、关联订单号 |
| 3 | 调用渠道支付 | 调用渠道统一下单接口，获取支付凭据（预支付 ID、二维码等） |
| 4 | 返回支付参数 | 返回前端 `<pay_params>` 用于调起支付 |
| 5 | 前端调起支付 | 前端根据渠道要求调起支付组件（扫码、跳转、弹窗小程序支付） |
| 6 | 用户完成支付 | 用户在渠道侧完成密码输入等操作 |
| 7 | 异步回调 | 渠道向支付网关回调地址 POST 支付结果通知 |
| 8 | 通知订单 | 支付网关校验签名后，发送 `transaction.updated` 事件，订单系统消费并推进状态 |
| 9 | 前端轮询 | 前端每 3 秒轮询订单详情接口，获取最新状态（最长轮询 5 分钟后退回待支付页） |
| 10 | 返回最新状态 | 订单系统返回当前订单状态 |

### 3.3 回调地址

- 正式环境：`https://pay.yunli.com/gateway/callback/{channel}`
- 沙箱环境：`https://sandbox.yunli.com/gateway/callback/{channel}`
- 回调限 IP 白名单，仅允许渠道官方 IP 段接入

## 4. 支付回调幂等设计

### 4.1 幂等键设计

- 第三方渠道使用 `pay_trade_no`（渠道流水号）作为唯一幂等键。
- 余额支付使用 `pay_order_no`（内部支付单号）作为唯一幂等键。
- `t_payment_order` 表对 `pay_trade_no` 建立唯一索引。

### 4.2 回调处理流程

```
回调到达 → 验签（失败直接返回 200，不处理）
  → 查重：SELECT id FROM t_payment_order WHERE pay_trade_no = ?
      ├─ 已存在且状态为成功 → 直接返回 200（重复回调）
      └─ 不存在或状态为非成功 → 继续处理
  → 校验金额：回调金额与支付单金额一致（不一致返回 200，挂告警工单）
  → 更新支付单状态为成功
  → 调用订单系统 updateOrderStatus 接口（幂等）
  → 返回 200 给渠道
```

### 4.3 重试与补偿

1. 渠道侧回调失败（网络超时等）会按渠道规则重试：微信和支付宝最长重试 3 天，间隔 10s/30s/5min/30min/1h/2h/6h/12h。
2. 支付网关侧回调订单系统失败，本地重试 3 次（间隔 5s/15s/30s），仍失败写入重试表，每 5 分钟扫描补偿一次。
3. 补偿上限 24 小时，超时仍未成功生成 P2 告警，客服端标记"订单已支付待人工确认"。

## 5. 支付超时与关单逻辑

### 5.1 支付超时

| 支付方式 | 支付超时时间 | 说明 |
|---|---|---|
| 微信支付 | 30 分钟 | 统一下单接口传入 `time_expire` 参数 |
| 支付宝 | 15 分钟 - 3 天（可配置） | 默认 30 分钟 |
| 银行卡 | 30 分钟 | 快捷支付凭证有效期 |
| 余额支付 | 30 分钟 | 与订单关单时间同步 |

### 5.2 关单流程

1. 订单系统定时任务（每 1 分钟执行）扫描创建时间超过 30 分钟且状态为"待付款"的订单。
2. 对每笔待关单订单，先查询支付网关对应支付单状态，若支付单已成功则先推进订单到"已付款"再关单。
3. 确认支付单为"未支付"或"已关闭"后，关单操作：
   a. 订单 → 已取消(60)
   b. 调用库存释放接口（幂等）
   c. 调用优惠券解冻接口（幂等）
   d. 写 `order_status_log`
4. 关单前 3 分钟给订阅了"支付提醒"的买家推送一条企微模板消息"您的订单即将关闭，请尽快支付"。

## 6. 对账机制

### 6.1 对账文件

| 渠道 | 对账文件获取方式 | 文件格式 | 获取时间 |
|---|---|---|---|
| 微信支付 | 下载对账单 API（每日） | CSV | 每日 09:00 前 |
| 支付宝 | 下载对账单 API（每日） | CSV | 每日 09:30 前 |
| 银联 | 对账 FTP 文件 | 固定格式文本 | 每日 10:00 前 |
| 余额账户 | 内部流水表 | 数据库 | 实时 |

### 6.2 对账比对

```
对账字段：
  平台侧：pay_order_no, pay_trade_no, pay_amount, pay_time, refund_amount
  渠道侧：trade_no, transaction_id, total_fee, time_end, refund_fee

比对规则：
  - 平台有渠道无：平台已记账但渠道无记录 → 未支付，拦截不可发货
  - 渠道有平台无：渠道已扣款但平台未收到 → 补单处理
  - 金额不一致：渠道金额 ≠ 平台金额 → 挂人工核对
  - 退款对账同上，比对退款金额与退款时间
```

### 6.3 差异处理优先级

| 差异类型 | 优先级 | 处理时限 | 处理方式 |
|---|---|---|---|
| 金额不一致 | P0 | 2 小时 | 立即冻结对应的订单支付，联系财务与渠道核实 |
| 渠道有平台无（收款） | P1 | 4 小时 | 补单，补写支付单和订单状态 |
| 渠道有平台无（退款） | P1 | 4 小时 | 补更新退款单状态 |
| 平台有渠道无（收款） | P2 | 24 小时 | 确认是否为渠道延迟，超过 T+2 方挂工单 |
| 平台有渠道无（退款） | P2 | 24 小时 | 重新发起退款请求 |

## 7. 常见错误码

| 错误码 | 说明 | 处理方式 |
|---|---|---|
| PAY_SUCCESS | 支付成功 | 正常推进 |
| PAY_USER_PAYING | 用户支付中，等待最终结果 | 轮询，不中断 |
| PAY_CLOSED | 支付单已关闭 | 引导用户重新下单 |
| PAY_NOTEXIST | 支付单不存在 | 检查 pay_order_no |
| PAY_REFUND | 已转入退款 | 联系客服 |
| PAY_FAIL | 支付失败 | 展示失败原因，引导重试或换支付方式 |
| PAY_SIGN_VERIFY_FAIL | 签名验证失败 | 拦截回调，告警，检查密钥 |
| PAY_AMOUNT_MISMATCH | 回调金额与订单金额不一致 | 拦截回调，挂人工工单 |
| PAY_TIMEOUT | 支付超时 | 前端提示超时，引导重新支付 |
| PAY_CHANNEL_UNAVAILABLE | 渠道不可用（维护中/余额不足/配额超限） | 切换备选渠道或展示不可用提示 |
| PAY_BALANCE_INSUFFICIENT | 余额不足 | 提示用户充值或换其他支付方式 |
| PAY_LIMIT_EXCEEDED | 单笔/单日支付限额 | 引导拆分支付或换渠道 |
| PAY_RISK_REJECT | 风控拦截 | 展示"本次交易存在风险，请联系客服" |
| PAY_CHANNEL_ERROR | 渠道内部错误 | 展示"支付服务异常，请稍后再试" |
| PAY_DUPLICATE_ORDER | 重复支付单 | 返回已有支付单参数，不重复创建 |
| PAY_REFUND_AMOUNT_EXCEED | 退款金额超过原支付金额 | 拒绝退款请求 |
| PAY_REFUND_FAIL | 渠道退款失败 | 转人工处理 |

## 8. 支付单表结构

表名：`t_payment_order`

| 字段名 | 类型 | 必填 | 说明 |
|---|---|---|---|
| id | bigint(20) | 是 | 主键，自增 |
| pay_order_no | varchar(32) | 是 | 支付单号，格式 `PY` + yyyyMMddHHmmss + 8 位随机 |
| order_no | varchar(32) | 是 | 关联订单号，支持一支付单多订单号（拆单场景） |
| channel | varchar(20) | 是 | 支付渠道：WECHAT/ALIPAY/BANKCARD/BALANCE/COMBINE |
| channel_sub_type | varchar(20) | 否 | 渠道子类型：JSAPI/APP/NATIVE/QUICK_PAY |
| pay_amount | decimal(12,2) | 是 | 应付金额，单位元 |
| paid_amount | decimal(12,2) | 是 | 实付金额，成功后回填 |
| refunded_amount | decimal(12,2) | 是 | 累计退款金额 |
| balance_amount | decimal(12,2) | 否 | 组合支付中余额支付金额，纯余额时等于 pay_amount |
| pay_trade_no | varchar(64) | 否 | 渠道流水号，唯一索引 |
| status | tinyint(4) | 是 | 支付单状态：0 待支付 / 1 支付中 / 2 已支付 / 3 已关闭 / 4 已退款 / 5 部分退款 |
| expire_time | datetime | 是 | 支付过期时间，超时自动关单 |
| pay_time | datetime | 否 | 支付成功时间 |
| notify_time | datetime | 否 | 最近一次回调通知时间 |
| notify_count | int(11) | 是 | 回调通知次数，默认 0 |
| raw_notify | text | 否 | 渠道回调原始报文，JSON 格式，用于对账排查 |
| create_time | datetime | 是 | 创建时间 |
| update_time | datetime | 是 | 更新时间 |
