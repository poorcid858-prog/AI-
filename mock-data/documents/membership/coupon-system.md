# 优惠券系统 PRD

## 1. 需求背景

云集商城券系统日发券量约 800 万张，月核销率 18%。原券系统仅支持满减券单一类型、无叠加互斥配置、无选优算法，会员经常"手里有券但不知道怎么用最省"，且运营配券依赖开发写脚本。本次重构建立统一券模型、可视化配券后台与多券选优引擎。

## 2. 业务目标

| 指标 | 当前值 | 目标值 |
|---|---|---|
| 券核销率 | 18% | 32% |
| 会员券包周访问 UV | 60 万 | 250 万 |
| 运营配券耗时（单个活动） | 2 天（需开发介入） | 30 分钟（自助配置） |
| 选优算法命中最优解率 | 无算法 | ≥99.5% |
| 券超发/超领投诉量（月） | 37 单 | 0 单 |

## 3. 优惠券类型

| 类型码 | 类型名 | 优惠逻辑 | 门槛 | 典型配置 |
|---|---|---|---|---|
| FULL_CUT | 满减券 | 订单满 X 元减 Y 元 | 有门槛 | 满 200 减 30 |
| DISCOUNT | 折扣券 | 订单金额打 X 折，可设最高优惠上限 | 可有可无 | 8 折，最高优惠 50 元 |
| NO_THRESHOLD | 无门槛券 | 直接减 Y 元 | 无门槛 | 无门槛 5 元 |
| FREIGHT | 运费券 | 抵扣运费，最高抵扣 Y 元 | 可设门槛 | 免运费（最高抵 12 元） |
| CATEGORY | 品类券 | 限定类目/品牌/SKU 范围内满 X 减 Y | 有门槛 | 服饰类满 300 减 60 |
| EXCHANGE | 兑换券 | 兑换指定商品，0 元或补差价 | 指定 SKU | 免费兑换指定小样 |

## 5. 发券方式

| 发券方式 | 渠道码 | 触发时机 | 库存校验 | 幂等键 |
|---|---|---|---|---|
| 主动领取 | SELF_GET | 会员在领券中心/商品页点击领取 | 校验 `remain_stock` 与 `per_member_limit` | member_id + template_id |
| 系统发放 | SYSTEM_SEND | 运营圈选人群批量推送 | 校验总库存，超发则截断并告警 | 批次号 + member_id |
| 新人券 | NEW_MEMBER | 注册完成后 1 分钟内自动发放 | 不限量 | member_id（一生一次） |
| 活动券 | ACTIVITY | 完成活动任务（签到、抽奖、分享） | 校验活动配置库存 | 活动 ID + member_id + 任务 ID |
| 等级礼包券 | LEVEL_GIFT | 会员升级时 / 每月 1 日券包发放 | 不限量 | member_id + 等级 + 期数 |
| 补偿券 | COMPENSATE | 客服或系统补偿发放 | 不限量，需审批留痕 | 工单号 |

### 5.1 领券并发控制

1. 领券库存扣减使用 **Redis Lua 原子脚本**：`if remain > 0 then decr remain; return 1 else return 0 end`。
2. Redis 扣减成功后异步落库写券实例；落库失败则回补 Redis 库存并记录补偿任务。
3. 会员限领校验与库存扣减在**同一个 Lua 脚本**内完成，避免"限领通过但库存已空"或"库存扣减但限领超出"。
4. 数据库侧对 `(member_id, template_id)` 建唯一约束（限领 1 张的模板），作为最终防线。
5. 热点券（预期 QPS >5000）开启库存分桶，将总库存拆为 10 个 Redis Key 分散热点。

## 6. 用券规则

### 6.1 使用条件校验

券可用需**同时满足**：

| 校验项 | 规则 |
|---|---|
| 券状态 | 必须为"未使用(1)" |
| 有效期 | `valid_start_time ≤ now ≤ valid_end_time` |
| 会员等级 | 若配置 `level_limit`，会员当前等级必须在列表内 |
| 使用门槛 | 适用范围内商品金额 ≥ `threshold_amount` |
| 适用范围 | 购物车内存在符合 `scope_type/scope_values` 的商品 |
| 归属校验 | 券归属会员与下单会员一致 |

### 6.2 叠加与互斥规则

| 规则 | 说明 |
|---|---|
| 独占券 | `exclusive_flag=1` 的券不与任何其他券同时使用 |
| 同组互斥 | `stackable_group` 相同的券最多用 1 张（如"店铺满减组"内只能选 1 张） |
| 跨组叠加 | 不同 `stackable_group` 的券可叠加，如"平台券 + 店铺券 + 运费券" |
| 单笔上限 | 单笔订单最多同时使用 **3 张**券（运费券不计入 3 张限制） |
| 类型限制 | 满减券与折扣券不可叠加使用（同属"金额优惠组"） |
| 运费券 | 独立于商品优惠，任何情况下可额外叠加 1 张 |
| 与积分叠加 | 券与积分可叠加，抵扣顺序：会员折扣 → 券 → 积分 |

### 6.3 优惠计算顺序

```
1. 商品原价合计
2. 会员等级折扣（如金卡 95 折）
3. 品类券 / 店铺券（作用于对应商品范围）
4. 平台券（作用于订单商品总额）
5. 折扣券或满减券（同组互斥，取其一）
6. 积分抵扣（上限：商品金额 30%，最高 200 元）
7. 运费券（只抵扣运费）
= 最终应付金额
```

**校验约束**：最终应付金额不得低于 **0.01 元**；若优惠总额超过商品金额，按商品金额 - 0.01 元截断，超出部分不生效。

## 7. 多券选优算法

### 7.1 算法目标

在会员持有的可用券中，选出**满足互斥规则前提下优惠金额最大**的券组合，并默认勾选。

### 7.2 算法实现

```
输入：购物车商品列表 items、会员持有可用券列表 coupons、会员等级 level
输出：最优券组合 bestCombo、优惠总额 maxDiscount

步骤：
1. 预筛选：过滤掉门槛不满足、适用范围不匹配、等级不符、已过期的券
   → 候选券集 C（实测 P99 规模 ≤ 40 张）
2. 分组：按 stackable_group 将 C 分组，独占券单独成组
3. 组内择优：每组内按"单券优惠金额"降序，只保留 Top 3（剪枝，降低组合爆炸）
4. 组合枚举：对分组做笛卡尔积，限制组合内券数 ≤3（运费券额外 1 张）
   → 组合数上限 3^3 × 3 = 81 种，可接受
5. 逐个组合试算：调用统一优惠计算引擎（第 6.3 节顺序）算出优惠总额
6. 择优：取优惠总额最大的组合；若并列，优先选"有效期更早到期"的券组合
7. 独占券对比：独占券单张试算结果与最优叠加组合对比，取更大者
```

### 7.3 算法约束

1. 选优结果**仅作默认勾选建议**，会员可手动改选，手动改选后不再自动覆盖。
2. 单次选优计算耗时要求 P99 ≤ 80ms，超时降级为"只选单张最大优惠券"。
3. 试算结果缓存 60 秒（缓存键含购物车指纹 + 会员 ID + 券包版本号），购物车变更立即失效。
4. 优惠券金额并列时提示会员"另有 X 张券优惠相同，可手动切换"。

## 8. 券的核销与退回

### 8.1 券的生命周期

```
未使用(1) --下单锁定--> 锁定中(2) --订单支付成功--> 已使用(3)
   ↑                        |
   |--订单取消/关单解锁-------|
   |
   --有效期到--> 已过期(4)
   --运营作废--> 已作废(5)
```

### 8.2 锁定与核销

| 环节 | 规则 |
|---|---|
| 下单锁定 | 订单创建时将券置为"锁定中"，写入 `lock_biz_no`=订单号，**不扣减** |
| 锁定超时 | 锁定超过 35 分钟（略大于订单关单 30 分钟）自动解锁，兜底任务每 5 分钟扫描 |
| 核销 | 订单支付成功后置为"已使用"，回填 `use_time`、`use_biz_no`、`actual_discount` |
| 核销幂等 | 以 `use_biz_no` 幂等，重复核销直接返回成功 |
| 解锁 | 订单取消/关单/支付失败时解锁回"未使用"，`lock_biz_no` 清空 |
| 解锁校验 | 解锁时校验券是否已过期，已过期则置为"已过期"，不再退回可用 |

### 8.3 券的退回规则

| 场景 | 券退回处理 |
|---|---|
| 订单未支付即取消 | 券解锁退回"未使用"，有效期不变 |
| 订单全额退款，券未过期 | 满减券/折扣券/品类券**原券退回**，有效期不变；活动券、新人券、补偿券**不退回** |
| 订单全额退款，券已过期 | 不退回原券，改发同等面额的补偿券，有效期 7 天 |
| 订单部分退款 | 券**不退回**（优惠已按商品金额占比分摊到未退商品） |
| 换货 | 券不退回不重新核销 |
| 退款被拒绝 | 券维持"已使用"状态不变 |

### 8.4 退回幂等与对账

1. 券退回以"退款单号 + 券码"为幂等键，重复调用不重复退回。
2. 每日 04:00 对账：核销券数 = 订单使用券数，差异写差异表并告警。
3. 监控项：日发券量、日核销量、券锁定超时未解锁数量（>100 触发告警）、超发券数量（应恒为 0）。

## 9. 券与会员等级的联动

优惠券是会员权益体系的主要承载形式，券系统需与会员等级、成长值、积分三者协同。

### 9.1 等级专属券包

| 会员等级 | 每月券包规格 | 券包总面额 | 发放时间 |
|---|---|---|---|
| 普通会员（L1） | 无券包 | — | — |
| 银卡会员（L2） | 3 张（满 100 减 5 ×2、运费券 ×1） | 20 元 | 每月 1 日 00:00 |
| 金卡会员（L3） | 6 张（满 200 减 20 ×2、满 100 减 10 ×2、运费券 ×2） | 80 元 | 每月 1 日 00:00 |
| 钻石会员（L4） | 10 张（满 500 减 100 ×1、满 200 减 40 ×3、无门槛 20 ×2、运费券 ×4） | 300 元 | 每月 1 日 00:00 |

### 9.2 等级相关的券类型

| 券用途 | 触发条件 | 券配置要点 |
|---|---|---|
| 升级礼包券 | 会员等级升级时发放 | `level_limit` 设为目标等级及以上；跨级升级时逐级发放 |
| 保级激励券 | 等级有效期剩 30 天且成长值未达保级线时发放 | 引导会员消费累积成长值，有效期 30 天 |
| 生日礼券 | 生日当月 1 日发放（银卡起） | 银卡 10 元 / 金卡 30 元 / 钻石 88 元，有效期为生日当月 |
| 等级日专享券 | 每月 8 号会员等级日 | 银卡满 200 减 20 / 金卡满 200 减 40 / 钻石满 200 减 80 |
| 降级挽回券 | 会员降级后 24 小时内发放 | 无门槛 15 元，引导会员回流，有效期 15 天 |
| 权益兑换商城券 | 会员使用积分兑换获得 | 兑换消耗积分，券面额由积分兑换比例换算 |
| 会员日大促券 | 会员运营配置活动 | 可按等级差异化配置面额，`level_limit` 控制可领范围 |

### 9.3 与会员权益的叠加关系

1. 会员等级折扣（银卡 98 折 / 金卡 95 折 / 钻石 92 折）**先于**优惠券生效，券的使用门槛按会员折扣后的金额判定。
2. 会员免运费权益与运费券**不重复叠加**，系统自动取优惠更大者：钻石会员本身无门槛全免，运费券不再消耗。
3. 券抵扣后才计算积分抵扣，积分抵扣上限按商品金额（非券后金额）的 30% 计算。
4. 会员成长值与积分按**券后实付金额**计算，券抵扣掉的部分不产生成长值与积分。
5. 券的领取与使用均可配置 `level_limit`，低等级会员领取时返回 `CP_LEVEL_NOT_MATCH`。
6. 会员降级后，已发放的高等级券**不回收**，可用至过期；下一期券包按新等级规格发放。

### 9.4 券对会员运营指标的影响

| 运营指标 | 券系统贡献点 |
|---|---|
| 会员等级升级转化率 | 保级激励券、等级日专享券引导消费累积成长值 |
| 会员月活跃度 | 每月券包发放触达 + 券即将过期提醒推送 |
| 会员流失挽回率 | 降级挽回券、沉睡会员唤醒券 |
| 会员权益使用率 | 券包核销率是权益使用率的主要构成项 |
| 积分消耗率 | 权益兑换商城以券作为主要兑换标的 |

## 10. 验收标准

1. 6 种券类型均可通过运营后台自助配置并成功发放、核销。
2. 1 万并发领取库存 100 张的热点券，实际发放张数严格等于 100，无超发。
3. 选优算法在会员持有 40 张券场景下 P99 耗时 ≤80ms，最优解命中率 ≥99.5%。
4. 单笔订单最多使用 3 张券 + 1 张运费券，超出被拦截；同组券互斥生效。
5. 订单取消后券在 5 分钟内退回"未使用"，全额退款后未过期券原券退回。
6. 最终应付金额永不为 0 或负数，最低 0.01 元。
7. 四个会员等级的每月券包按第 9.1 节规格准确发放，发放成功率 ≥99.99%。
8. 会员等级折扣、优惠券、积分抵扣三者叠加顺序正确，最终金额与手工计算一致。
9. 会员降级后已发放券不被回收，下一期券包按新等级规格发放。
10. 券的 `level_limit` 配置生效：低等级会员领取与使用均被正确拦截。
