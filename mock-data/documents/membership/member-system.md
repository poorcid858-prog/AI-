# 会员体系 PRD

## 1. 需求背景

云集商城注册会员 2400 万，其中 30 天活跃会员 380 万。原会员体系仅有"普通/VIP"两档，权益单薄，高价值会员缺乏差异化感知，会员年度复购率仅 32%。本次升级建立四级会员等级体系，引入成长值模型与权益矩阵，通过等级感知与专属权益提升会员留存与复购。

## 2. 业务目标

| 指标 | 当前值 | 目标值 |
|---|---|---|
| 会员年度复购率 | 32% | 45% |
| 金卡及以上会员占比 | — | 8% |
| 会员权益使用率（至少用过 1 项） | 21% | 60% |
| 会员等级页月访问 UV | 45 万 | 200 万 |
| 高等级会员客单价相对普通会员溢价 | 1.4 倍 | 2.0 倍 |

## 3. 会员等级定义

### 3.1 等级与升级条件

| 等级码 | 等级名 | 升级所需成长值 | 保级所需成长值（年度） | 徽章样式 |
|---|---|---|---|---|
| L1 | 普通会员 | 0 | — | 灰色 |
| L2 | 银卡会员 | 1000 | 800 | 银色 |
| L3 | 金卡会员 | 5000 | 4000 | 金色 |
| L4 | 钻石会员 | 20000 | 16000 | 钻石渐变 |

### 3.2 升级判定规则

1. **实时升级**：成长值到达阈值时立即升级，无需等待周期结算，升级后 App 弹出升级动效与专属权益礼包。
2. **等级有效期**：升级后等级有效期为 **12 个自然月**，有效期内不因成长值波动而降级。
3. **续期**：等级有效期内累计新增成长值达到"保级所需成长值"，有效期自动续期 12 个月。
4. **跨级升级**：允许一次跨级（如一笔大额消费从银卡直升钻石），跨级时逐级发放各等级的升级礼包。
5. **等级只看成长值**，不看历史消费总额、不看注册时长。

### 3.3 各等级专属权益

| 权益项 | 普通会员 | 银卡会员 | 金卡会员 | 钻石会员 |
|---|---|---|---|---|
| 全站商品折扣 | 无折扣 | 98 折 | 95 折 | 92 折 |
| 免运费门槛 | 满 99 元 | 满 79 元 | 满 39 元 | 无门槛全免 |
| 消费成长值倍率 | 1.0 倍 | 1.2 倍 | 1.5 倍 | 2.0 倍 |
| 消费积分倍率 | 1.0 倍 | 1.2 倍 | 1.5 倍 | 2.0 倍 |
| 生日礼 | 无 | 生日券 10 元 | 生日券 30 元 + 双倍积分 | 生日券 88 元 + 三倍积分 + 定制礼盒 |
| 每月专属券包 | 无 | 3 张（合计 20 元） | 6 张（合计 80 元） | 10 张（合计 300 元） |
| 专属客服通道 | 无 | 无 | 优先接入（排队权重 ×2） | 1v1 专属顾问 |
| 售后时效延长 | 7 天 | 7 天 | 15 天 | 30 天 |
| 新品优先购 | 无 | 无 | 提前 6 小时 | 提前 24 小时 |
| 等级日专享（每月 8 号） | 无 | 满 200 减 20 | 满 200 减 40 | 满 200 减 80 |
| 免费退货运费次数（年） | 0 次 | 2 次 | 6 次 | 12 次 |
| 权益兑换商城折扣 | 无 | 9 折 | 8 折 | 7 折 |

### 3.4 权益生效与失效

1. 权益随等级实时生效，升级后立即可用，无延迟。
2. 折扣权益作用于商品价格，与优惠券叠加顺序为：**先会员折扣，后优惠券抵扣**。
3. 每月专属券包在每月 1 日 00:00 自动发放至会员券包，有效期 30 天，逾期不补。
4. 生日礼在生日当月 1 日发放，需会员已完善出生日期；出生日期每年只允许修改 1 次，修改后当年不再发放生日礼。
5. 降级后当期已发放但未使用的高等级券**不回收**，但下一期按新等级发放。
6. 免费退货运费次数按等级有效期计算，降级后剩余次数按新等级上限截断。

## 4. 成长值规则

### 4.1 成长值获取途径

| 途径 | 成长值 | 上限 | 说明 |
|---|---|---|---|
| 消费（订单完成） | 实付金额 1 元 = 1 成长值 × 等级倍率 | 无上限 | 订单完成（确认收货）后 T+1 发放 |
| 每日签到 | 2 | 每日 1 次 | 连续签到第 7 天额外 +10 |
| 完善会员资料 | 50 | 一次性 | 补全昵称、性别、生日、职业标签 |
| 绑定手机号 | 30 | 一次性 | — |
| 首次实名认证 | 100 | 一次性 | — |
| 商品评价（含图） | 5 | 每日上限 25 | 纯文字评价 2 成长值 |
| 分享商品/邀请好友 | 10 / 有效邀请 | 每月上限 200 | 被邀请人完成首单方计为有效邀请 |
| 参加会员活动 | 活动配置 | 单活动配置 | 由会员运营在活动后台配置 |

### 4.2 成长值扣减规则

| 场景 | 扣减规则 |
|---|---|
| 订单全额退款 | 扣回该订单发放的全部成长值 |
| 订单部分退款 | 按退款金额比例扣回，向下取整 |
| 恶意刷单被判定 | 扣回全部相关成长值，并冻结成长值账户 30 天 |
| 评价被删除（违规） | 扣回该评价获得的成长值 |
| 邀请的好友退款且全额退回 | 扣回该次邀请奖励成长值 |

**允许成长值为负**：扣减后账户可为负值，后续新增成长值优先填补负值，等级不会因扣减导致有效期内降级。

### 4.3 成长值清零与统计口径

1. 成长值账户设两个数值：
   - `total_growth`：累计成长值，永不清零，仅用于展示"历史总成长"。
   - `period_growth`：本等级周期成长值，用于升级与保级判定。
2. `period_growth` 在**等级有效期结束时结算并清零**，重新开始累计。
3. 结算逻辑：有效期到期日 00:30 执行批量任务，比对 `period_growth` 与保级阈值，决定续期或降级。
4. 成长值获取实时到账（消费类 T+1），账户流水表 `t_growth_log` 保留 3 年，会员可在 App 查询近 12 个月明细。

## 5. 等级降级规则

### 5.1 降级触发

| 触发条件 | 降级结果 |
|---|---|
| 等级有效期到期且 `period_growth` < 保级阈值 | 降 **1 级**（不跨级降级） |
| 连续两个周期均未达保级阈值 | 再降 1 级，最低降至普通会员 |
| 账号因违规被处罚（刷单、恶意退货、虚假评价） | 直接降为普通会员，且 180 天内不可升级 |
| 会员主动注销后重新注册 | 新账号从普通会员起算，旧等级不继承 |

### 5.2 降级保护与提醒

1. **降级预警**：有效期到期前 30 天、7 天、1 天各推送一次提醒，展示"还需 X 成长值即可保级"。
2. **宽限期**：到期时成长值达到保级阈值的 80% 以上，给予 15 天宽限期补足，宽限期内保持原等级与权益。
3. **一次性保级卡**：钻石会员每 24 个月可使用 1 张保级卡，直接续期 12 个月（发放在钻石升级礼包内）。
4. 降级后立即按新等级计算折扣、免运费门槛、成长值倍率与积分倍率。

### 5.3 权益回收清单

| 权益 | 降级后处理 |
|---|---|
| 商品折扣率 | 立即按新等级执行 |
| 免运费门槛 | 立即按新等级执行 |
| 成长值/积分倍率 | 立即按新等级执行，已发放的不追回 |
| 已发放未使用的券 | 不回收，可正常使用至过期 |
| 专属客服通道 | 立即回收，下次咨询按新等级排队 |
| 售后时效延长 | 已产生的订单按下单时等级享受，新订单按新等级 |
| 免费退货运费次数 | 剩余次数按新等级上限截断（如从 6 次剩 5 次降为银卡则截断为 2 次） |
| 权益兑换商城折扣 | 立即按新等级执行 |

## 7. 会员权益使用与核销

### 7.1 权益核销记录

表名：`t_benefit_use_log`

| 字段名 | 类型 | 必填 | 说明 |
|---|---|---|---|
| log_id | bigint(20) | 是 | 主键 |
| member_id | bigint(20) | 是 | 会员 ID |
| benefit_code | varchar(30) | 是 | 权益编码：DISCOUNT/FREE_FREIGHT/BIRTHDAY_GIFT/MONTHLY_COUPON/FREE_RETURN/AHEAD_BUY/EXCLUSIVE_SERVICE |
| level_snapshot | varchar(4) | 是 | 使用时的会员等级快照，用于争议核对 |
| biz_no | varchar(64) | 否 | 关联业务单号，幂等键 |
| benefit_value | varchar(50) | 否 | 权益值快照，如折扣率 0.95、抵扣运费 12.00 |
| use_time | datetime | 是 | 使用时间 |

### 7.2 权益使用约束

| 权益 | 约束 |
|---|---|
| 商品折扣 | 每笔订单自动生效，不需要会员主动选择；特价与秒杀商品不叠加会员折扣 |
| 免运费 | 按订单商品金额判定门槛，钻石会员无门槛；与运费券不重复抵扣，取优惠更大者 |
| 生日礼 | 每年一次，生日当月 1 日发放，需已填生日且当年未改过生日 |
| 每月券包 | 每月 1 日发放，同一期数重复执行任务不重复发放（幂等键：会员 ID + 期数） |
| 免费退货运费 | 按次核销，核销时校验剩余次数，次数为 0 时不再抵扣 |
| 新品优先购 | 按商品开售时间前移，非会员在开售前访问返回"商品未开售" |
| 专属客服 | 金卡起排队权重 ×2，钻石会员直连专属顾问 |

### 7.3 权益争议处理原则

1. 以 `t_benefit_use_log` 中的 `level_snapshot` 为准，判断当时会员是否具备该权益。
2. 订单相关权益（售后时效、免运费）按**下单时**等级享受，即使之后降级也不追回。
3. 因系统故障导致权益未生效，核实后由会员运营补发等值券或积分补偿。
4. 权益补偿需走审批留痕，补偿记录写入 `t_benefit_use_log` 并标记 `benefit_code=COMPENSATE`。

## 8. 会员等级变更事件

等级变更时发送 `member.level.changed` 事件，供下游订阅：

| 订阅方 | 消费动作 |
|---|---|
| 权益缓存服务 | 立即失效该会员的权益缓存，避免降级后仍享受高等级折扣 |
| 券服务 | 升级则发放对应等级礼包券；降级则不回收已发券，仅调整下期发放规格 |
| 积分服务 | 更新会员积分倍率 |
| 成长值服务 | 更新会员成长值倍率 |
| 消息中心 | 升级推送祝贺消息与权益介绍；降级推送提醒与"如何重新升级"引导 |
| 数据看板 | 更新各等级会员数量统计 |

### 8.1 事件体示例

```json
{
  "eventId": "evt_20260811_0001",
  "eventType": "member.level.changed",
  "memberId": "m_10000123",
  "changeType": "UPGRADE",
  "fromLevel": "L2",
  "toLevel": "L3",
  "triggerSource": "GROWTH_REACH",
  "periodGrowth": 5010,
  "levelExpireTime": "2027-08-11 00:00:00",
  "eventTime": "2026-08-11 14:30:00"
}
```

`changeType` 取值：`UPGRADE` 升级 / `KEEP` 保级续期 / `GRACE` 进入宽限期 / `DOWNGRADE` 降级 / `PUNISH` 违规降级。

## 9. 数据一致性与幂等

| 场景 | 幂等键 | 保障手段 |
|---|---|---|
| 成长值发放 | 来源业务单号（订单号/签到日期/活动 ID） | 流水表唯一索引 |
| 成长值扣回 | 退款单号 | 流水表唯一索引 |
| 等级升级 | 会员 ID + 目标等级 + 周期序号 | 升级礼包发放幂等 |
| 周期结算 | 会员 ID + 周期序号 | 结算任务可重复执行，结果一致 |
| 月度券包发放 | 会员 ID + 期数 | 券服务侧幂等校验 |
| 生日礼发放 | 会员 ID + 年份 | 券服务侧幂等校验 |
| 权益核销 | 业务单号 + 权益编码 | 核销日志唯一索引 |

**账户变更**：`t_member_account` 更新均带 `version` 乐观锁，冲突重试 3 次；成长值流水与账户更新在同一本地事务内完成。

## 10. 监控与告警

| 监控指标 | 阈值 | 告警级别 |
|---|---|---|
| 周期结算任务执行时长 | >30 分钟 | P1 |
| 周期结算任务失败会员数 | >100 | P0 |
| 成长值流水与账户余额差异 | ≥1 个会员不一致 | P1 |
| 单会员单日成长值发放异常 | >50000 成长值 | P1（转风控审查） |
| 月度券包发放成功率 | <99.99% | P1 |
| 生日礼重复发放 | ≥1 笔 | P0 |
| 等级变更事件积压 | >1000 条 | P2 |
| 权益缓存命中率 | <90% | P2 |
| 降级后权益未生效（抽样巡检） | ≥1 例 | P0 |

## 11. 验收标准

1. 四个等级的升级、保级、降级、宽限期四条路径可通过接口与定时任务完整触发。
2. 成长值实时到账（消费类 T+1），账户流水与账户余额一致，差异为 0。
3. 会员折扣与优惠券叠加顺序正确：先会员折扣后券抵扣，最终金额与手工计算一致。
4. 有效期到期批量结算 380 万活跃会员，任务执行时长 ≤30 分钟，结果可回滚。
5. 降级后专属客服通道、折扣率、免运费门槛、免费退货次数在 1 分钟内全部按新等级生效。
6. 每月 1 日券包发放任务对全量会员执行，发放成功率 ≥99.99%，失败可重试补发。
7. 周期结算任务重复执行两次，结算结果一致，不出现重复升级或重复扣减。
8. `member.level.changed` 事件的 6 个订阅方全部正确消费，权益缓存 1 分钟内失效。
9. `total_growth` 在任何场景下均不被清零，仅 `period_growth` 在周期结算时清零。
10. 生日礼、月度券包在同一周期内重复触发任务不重复发放。
11. 查询会员信息接口在 10000 QPS 下 P99 ≤100ms，成功率 ≥99.99%。
12. 第 10 节全部监控指标已配置，告警可正常触达会员业务值班群。
