# 积分规则文档

> 积分是云集商城会员权益体系的通用激励货币，与会员等级、成长值共同构成会员运营三支柱。本文档定义积分的获取、使用、有效期、冻结与回退全部口径。

## 1. 积分基础设定

| 项 | 规则 |
|---|---|
| 积分名称 | 云集积分（对外称"云豆"） |
| 兑换比例 | 100 积分 = 1 元 |
| 最小使用单位 | 100 积分（不足 100 积分不可抵扣） |
| 积分精度 | 整数，不支持小数 |
| 积分是否可转赠 | 不可转赠、不可提现、不可交易 |
| 积分账户唯一性 | 一个会员 ID 对应一个积分账户 |

## 2. 积分获取途径

| 途径 | 积分计算 | 单次上限 | 周期上限 | 到账时效 |
|---|---|---|---|---|
| 消费得积分 | 订单实付金额 1 元 = 1 积分 × 会员等级积分倍率 | 无 | 无 | 订单完成后 T+1 |
| 每日签到 | 第 1-3 天 5 分 / 第 4-6 天 10 分 / 第 7 天 30 分 | 30 | 每日 1 次 | 实时 |
| 连续签到满 30 天 | 额外 200 积分 | 200 | 每自然月 1 次 | 实时 |
| 商品评价（纯文字） | 10 积分 | 10 | 每日 5 单 | 实时 |
| 商品评价（图片 ≥3 张） | 30 积分 | 30 | 每日 5 单 | 实时 |
| 商品评价（视频） | 50 积分 | 50 | 每日 3 单 | 实时 |
| 分享商品至社交平台 | 5 积分 | 5 | 每日上限 25 积分 | 实时 |
| 邀请好友注册并完成首单 | 500 积分 | 500 | 每月上限 5000 积分 | 好友首单完成后 T+1 |
| 完善会员资料 | 100 积分 | 100 | 一次性 | 实时 |
| 参加会员活动 | 活动后台配置 | 活动配置 | 活动配置 | 活动规则 |
| 会员等级升级礼 | 银卡 500 / 金卡 2000 / 钻石 8000 | — | 每等级一次性 | 升级时实时 |
| 生日双倍积分 | 生日当月消费积分翻倍（金卡起） | — | 每年生日月 | 与消费积分同步 |

### 2.1 获取规则约束

1. 消费积分只按**实付金额**计算，不含运费、不含积分抵扣掉的部分。
2. 使用积分抵扣的那部分金额**不再产生新积分**（防止套利循环）。
3. 签到跨天判定以**服务端时区（Asia/Shanghai）当日 00:00:00**为界，客户端时间不作为依据；同一自然日重复调用签到接口返回"今日已签到"，不重复发放。
4. 连续签到中断（漏签 1 天）则天数归零，从第 1 天重新计算。
5. 评价积分在评价审核通过后发放；评价被删除或判定违规则扣回。

## 3. 积分使用规则

### 3.1 抵扣规则

| 规则项 | 值 |
|---|---|
| 抵扣比例 | 100 积分 = 1 元 |
| 单笔订单最高抵扣比例 | 订单商品金额的 **30%** |
| 单笔订单最高抵扣积分 | 20000 积分（即 200 元） |
| 最低使用门槛 | 单笔至少使用 500 积分 |
| 抵扣步长 | 100 积分的整数倍 |
| 是否可与优惠券叠加 | 可以，抵扣顺序：会员折扣 → 优惠券 → 积分抵扣 |
| 是否可抵扣运费 | 不可，积分只抵扣商品金额 |

**计算示例**：商品金额 1000 元，金卡会员 95 折后 950 元，使用满 500 减 50 券后 900 元。
- 积分最高抵扣 = `min(1000 × 30%, 200)` = 200 元 = 20000 积分
- 会员积分余额 15000 → 实际抵扣 150 元 → 实付 750 元
- 本单获得消费积分 = `750 × 1.5（金卡倍率）` = 1125 积分（抵扣部分不算）

### 3.2 不可抵扣商品范围

| 范围 | 说明 |
|---|---|
| 虚拟商品 | 充值卡、话费、会员卡、电子券 |
| 特价秒杀商品 | 商品标记 `no_points_deduct = 1` |
| 预售商品定金 | 定金阶段不可抵扣，尾款阶段可抵扣 |
| 权益兑换商城商品 | 已为积分兑换专区，不可再抵扣 |
| 第三方联营特定类目 | 图书、生鲜（结算模式限制） |

**混合购物车处理**：购物车含可抵扣与不可抵扣商品时，积分抵扣上限只按**可抵扣商品金额**的 30% 计算，抵扣金额只分摊到可抵扣商品明细行。

## 4. 积分有效期与过期规则

| 规则项 | 值 |
|---|---|
| 有效期 | 自获取之日起 **24 个自然月** |
| 过期时点 | 每年 12 月 31 日 23:59:59 统一清算上上年获得的积分 |
| 扣减顺序 | **先到期先扣**（FIFO），优先消耗即将过期的积分 |
| 过期提醒 | 过期前 30 天、7 天各推送一次，展示即将过期积分数 |
| 过期后处理 | 不可恢复、不可补发 |
| 过期积分是否影响等级 | 不影响，会员等级只看成长值 |

**批次化管理**：积分按获取批次存储于 `t_point_batch`，每批次记录 `point_amount`、`used_amount`、`expire_time`，抵扣时按 `expire_time` 升序消耗批次。

## 5. 积分冻结与解冻

### 5.1 冻结场景

| 场景 | 冻结规则 | 解冻条件 |
|---|---|---|
| 下单使用积分抵扣 | 下单时冻结抵扣积分，不立即扣减 | 订单完成后转为真实扣减 |
| 订单未完成期间 | 冻结状态，会员端展示"冻结中" | 订单取消/关单则全额解冻退回 |
| 消费获得的积分 | 订单完成前不发放，无冻结概念 | 订单完成 T+1 发放 |
| 账号风险审查 | 全账户积分冻结，不可使用 | 风控审查通过后解冻 |
| 违规行为待处理 | 涉事积分冻结 | 处理结论：扣回或解冻 |

### 5.2 冻结账户口径

```
可用积分 = 总积分 - 冻结积分
总积分 = Σ 各批次 (point_amount - used_amount)
冻结积分 = Σ 处理中订单的抵扣积分 + 风控冻结积分
```

**冻结校验**：抵扣时校验 `可用积分 ≥ 本次抵扣积分`，不足返回 `PT_INSUFFICIENT`。冻结操作以订单号作幂等键，重复冻结不叠加。

## 6. 积分回退规则

| 场景 | 抵扣积分处理 | 消费积分处理 |
|---|---|---|
| 订单取消（未支付） | 全额解冻退回，有效期不变 | 未发放，无需处理 |
| 订单全额退款 | 全额回退至原批次，继承原有效期 | 全额扣回该订单发放的消费积分 |
| 订单部分退款 | 按退款商品金额占比回退，向下取整 | 按退款金额比例扣回，向下取整 |
| 退款时原积分批次已过期 | 回退至**新批次**，有效期为回退日起 3 个月 | — |
| 扣回时积分余额不足 | — | 允许账户为负，后续新增积分优先填补 |
| 换货 | 不回退不扣减（资金流不变） | 不变 |

**回退计算示例**：订单实付 750 元（抵扣 150 元 = 15000 积分），退款其中 300 元商品（占商品金额 30%）。
- 回退抵扣积分 = `15000 × 30% = 4500 积分`（向下取整）
- 扣回消费积分 = `1125 × 300/750 = 450 积分`（向下取整）

## 7. 积分账户字段说明

### 7.1 积分账户表

表名：`t_point_account`

| 字段名 | 类型 | 必填 | 说明 |
|---|---|---|---|
| member_id | bigint(20) | 是 | 会员 ID，主键 |
| total_point | bigint(20) | 是 | 总积分（含冻结），允许为负 |
| available_point | bigint(20) | 是 | 可用积分 = total_point - frozen_point |
| frozen_point | bigint(20) | 是 | 冻结积分，默认 0 |
| accumulated_point | bigint(20) | 是 | 历史累计获得积分，只增不减，用于展示 |
| used_point | bigint(20) | 是 | 历史累计使用积分 |
| expired_point | bigint(20) | 是 | 历史累计过期积分 |
| status | tinyint(4) | 是 | 账户状态：1 正常 / 2 全额冻结（风控） |
| version | int(11) | 是 | 乐观锁版本号，每次变更 +1 |
| update_time | datetime | 是 | 最近变更时间 |

### 7.2 积分批次表

表名：`t_point_batch`

| 字段名 | 类型 | 必填 | 说明 |
|---|---|---|---|
| batch_id | bigint(20) | 是 | 批次 ID，主键 |
| member_id | bigint(20) | 是 | 会员 ID，联合索引 (member_id, expire_time) |
| point_amount | bigint(20) | 是 | 该批次获得积分数 |
| used_amount | bigint(20) | 是 | 该批次已使用积分数 |
| source_type | varchar(20) | 是 | 来源：CONSUME/SIGN_IN/REVIEW/SHARE/INVITE/ACTIVITY/LEVEL_UP/REFUND_BACK |
| source_biz_no | varchar(64) | 否 | 来源业务单号，幂等键 |
| get_time | datetime | 是 | 获得时间 |
| expire_time | datetime | 是 | 过期时间 = get_time + 24 个月 |
| status | tinyint(4) | 是 | 批次状态：1 有效 / 2 已用尽 / 3 已过期 |

### 7.3 积分流水表

表名：`t_point_log`

| 字段名 | 类型 | 必填 | 说明 |
|---|---|---|---|
| log_id | bigint(20) | 是 | 流水 ID，主键 |
| member_id | bigint(20) | 是 | 会员 ID |
| change_type | varchar(20) | 是 | 变更类型：GET/USE/FREEZE/UNFREEZE/REFUND_BACK/DEDUCT/EXPIRE |
| change_amount | bigint(20) | 是 | 变更数量，正数为增加，负数为减少 |
| balance_after | bigint(20) | 是 | 变更后总积分余额，用于对账 |
| batch_id | bigint(20) | 否 | 关联批次 ID，多批次消耗时拆多条流水 |
| biz_type | varchar(20) | 是 | 业务类型：ORDER/SIGN_IN/REVIEW/ACTIVITY/SYSTEM |
| biz_no | varchar(64) | 否 | 业务单号，与 change_type 组成唯一索引做幂等 |
| remark | varchar(200) | 否 | 流水备注，会员端展示文案 |
| create_time | datetime | 是 | 流水时间 |

## 8. 积分对账与监控

1. 每日 03:00 校验：`total_point == Σ 批次(point_amount - used_amount)`，差异写差异表并告警。
2. 每日校验：`Σ 流水 change_amount == total_point`，不一致触发 P1 告警。
3. 监控指标：日发放积分总量、日消耗积分总量、积分负债余额、单会员单日发放异常（>50000 积分触发风控审查）。
4. 积分负债（未消耗积分总量 × 0.01 元）每月上报财务计提。
