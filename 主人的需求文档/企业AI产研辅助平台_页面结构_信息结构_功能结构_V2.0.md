## 3. 信息结构图

### 3.1 AI工作台

核心对象为AI工作台会话/任务。

重要字段： - 会话ID - 助手类型（产品/测试/前端等） - 用户输入 -
意图识别结果 - 执行状态 - 最终输出 - 满意度评分 - 创建时间

功能需要支持记录AI交互、执行链路、用户反馈、历史记录和历史对话。

### 3.2 知识中心

#### 文档

重要字段： - 文档ID - 名称 - 类型 - 版本 - 业务线 - 状态 - 创建人 -
创建时间

文档是知识资产父级对象，一个文档可以对应多个Chunk。

#### Chunk

重要字段： - Chunk ID - 文档ID - 内容 - 序号 - 业务线 - 知识类型 -
适用角色 - 适用场景 - 版本 - 权限 - Embedding

Chunk是文档子级数据，用于RAG检索。元数据用于分类、检索过滤、权限控制和场景匹配。

### 3.3 能力中心

#### AI能力（能力聚合视图）

重要字段： - AI能力ID - 名称 - 描述 - 覆盖岗位 - 关联Workflow - 状态 - 版本 - 创建人 - 创建时间

AI能力是面向用户的业务能力，关联一个 Workflow。Workflow 已经包含了 Skill、Reference、Prompt、Tool/Script 等要素，所以选择 Workflow 即确定了能力的技能组合。能力列表展示每个能力关联的 Workflow 及其全部要素。

#### Workflow

重要字段： - Workflow ID - 名称 - 描述 - 节点 - 节点顺序 - 状态 - 版本 -
创建人 - 创建时间

Workflow负责组织执行流程，可调用Skill、RAG、Reference、Prompt、Tool/Script。**Workflow 不是空壳，配置 Workflow 时需要选定它包含的 Skill、Reference、Prompt、Tool/Script 等要素。**

#### Skill

重要字段： - Skill ID - 名称 - 描述 - 输入参数 - 输出格式 - 规则 -
约束 - 所属业务线 - 关联Prompt - 状态 - 版本

Skill负责完成具体专业任务，例如需求分析、PRD生成、测试用例生成、代码生成。

#### Reference

重要字段： - Reference ID - 名称 - 类型（模板/案例/规范等） - 来源 -
内容 - 适用范围 - 版本 - 状态

#### Prompt

重要字段： - Prompt ID - 名称 - 类型（全局/角色/Workflow/Skill等） -
内容 - 版本 - 状态

Prompt采用：

``` text
全局Prompt
↓
角色Prompt
↓
Workflow Prompt
↓
Skill Prompt
↓
用户输入
```

最终模型输入可组合：全局规则、角色规则、Workflow规则、Skill规则、Reference、RAG知识、用户需求。

#### Tool / Script

重要字段： - ID - 名称 - 类型（Tool/Script） - 描述 - 输入参数 -
输出结果 - API/接口 - 执行逻辑 - 权限 - 状态

Tool负责调用外部能力/系统；Script负责执行固定、确定性的程序逻辑。

### 3.4 审核中心

提交人 - 提交时间 - 审核人 - 审核时间 - 审核状态（待审核/通过/驳回） -

## 8. 开发AI必须遵守的原则

1.  用户默认通过自然语言使用AI，不强制选择任务类型。
2.  AI能力不是Workflow本身，Workflow是AI能力背后的执行流程。
3.  RAG不是Skill的固定子步骤，而是Workflow可以调用的知识获取能力。
4.  知识中心负责知识资产管理，RAG负责运行时知识检索。
5.  Skill负责专业任务能力，不等于Prompt。
6.  Reference负责模板、规范、案例，不等于RAG。
7.  Tool负责外部系统调用，Script负责确定性的程序执行。
8.  Chunk属于文档的子级数据，必须保留document_id父子关系。
9.  Prompt采用分层设计。
10. 每次AI执行必须记录完整执行链路，支持问题定位。
11. 普通用户不能修改Workflow、Skill、Prompt等AI能力配置。
12. 能力必须经过测试、审核、发布后才能正式被AI工作台调用。
13. 系统管理负责平台基础配置，运营中心负责AI业务效果分析。
14. 模型统一在系统管理中配置，Workflow只引用已经配置好的模型。
15. 不要把RAG、Skill、Reference、Workflow等底层概念直接暴露给普通用户。
16. 页面结构不能脱离六大模块。
17. 页面上的功能必须对应具体业务对象。
18. 核心对象必须有唯一ID。
19. 知识、能力和AI结果需要支持审核流程。
20. 页面字段设计必须服务于实际业务，不增加没有业务用途的字段。

## 9. 给代码AI的核心理解

> 这是一个企业内部AI产研辅助平台。用户从AI工作台通过自然语言提出需求，系统通过意图识别将请求路由到对应的AI能力和Workflow。Workflow根据任务需要调用RAG、Skill、Reference、Prompt以及Tool/Script，并最终调用模型生成结果。知识中心负责企业知识资产和Chunk管理，能力中心负责AI能力的创建与编排，审核中心负责审核，运营与管理中心负责使用效果和问题定位，系统管理负责用户、角色、权限、模型、日志及系统配置。平台所有核心对象都需要建立明确的数据关系，并且AI执行过程需要保留完整链路，支持后续分析和问题定位。
