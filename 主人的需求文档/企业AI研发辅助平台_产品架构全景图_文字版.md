# 企业AI研发辅助平台——产品架构图（全景）文字版

> 本文档严格依据《企业AI研发辅助平台—产品架构图（全景）》图片转写。
>
> **核心愿景：**让研发人员基于企业知识，借助AI能力，更高效地完成需求分析、文档编写、测试设计、代码实现等工作。

> 本文保留原图的模块层级、角色、能力、知识生命周期、Reference体系、一次任务执行流程、各要素职责、反馈闭环、产品价值与数据资源底座。

主要使用场景：

- 代码生成
- 代码解释
- 接口文档生成
- 技术方案分析

## 4. 其他角色

- UI设计

# 五、2. AI能力中心（能力供给）

## 5.1 定位

AI能力中心负责给AI工作台提供可复用的能力组件和执行编排能力。

核心组成：

```text
AI能力（能力聚合视图，以AI能力为单位展示）
Workflow（已包含Skill / Reference / Prompt / Tool / Script等要素）
Skill
Tool & Script
Reference
Prompt
```

---

## 5.2 Workflow（工作流编排）

### 作用

定义任务流程、步骤、条件分支以及顺序/执行。

也就是说：

> Workflow主要解决“这个任务应该怎么一步一步做”。

### 核心职责

```text
定义任务流程
定义执行步骤
定义条件分支
定义执行顺序
```

---

## 5.3 Skill（专业能力）

### 作用

针对特定任务提供专业能力。

原图强调 Skill 与以下内容相关：

```text
Prompt
规则
知识
输出格式
```

因此 Skill 的定位可以理解为：

> 把某一种具体任务所需要的方法、规则、Prompt、知识以及输出要求组织成可复用的专业能力。

例如：

```text
需求分析Skill
PRD生成Skill
测试用例生成Skill
代码生成Skill
质量检查Skill
```

---

## 5.4 Tool & Script（工具与脚本）

### Tool

用于：

> 调用外部工具。

例如：

```text
调用外部系统
调用API
调用搜索服务
调用模型服务
调用导出能力
```

### Script

用于：

> 执行脚本来完成确定性的处理操作。

例如：

```text
规则处理
数据处理
格式处理
固定逻辑执行
Prompt拼装
检索参数构造
```

核心区别：

```text
Skill
= 专业任务能力

Tool
= 调用外部工具 / 系统能力

Script
= 执行确定性的脚本逻辑
```

# 七、知识生命周期

完整知识处理链路：

```text
原始文档
    ↓
标准化文档
    ↓
Chunk
    ↓
向量化数据
```

---

## 7.1 原始文档

### 处理方式

- 上传 / 收集
- 多源文档

说明：

> 企业知识可能来自多个来源，首先进入原始文档层。

---

## 7.2 标准化文档

### 处理方式

- 清洗 / 解析
- 规范化处理

说明：

> 对原始文档进行清洗、解析和规范化，形成可用于后续知识处理的标准化文档。

---

## 7.3 Chunk

### 处理方式

- 智能切分
- 结构化片段

说明：

> 将标准化文档进一步智能切分成适合检索的结构化知识片段。

---

## 7.4 向量化数据

### 处理方式

```text
Embedding
向量存储
```

说明：

> 将Chunk进行Embedding，形成可用于向量检索的向量化数据。

---

```text
    ↓
⑦ 大模型生成
    ↓
⑧ 质量检查
    ↓
⑨ 结果返回与处理
    ↓

    ↺
```

原图的主流程使用实线表示，反馈/回流使用虚线表示。

# 十二、① 意图识别

## 标题

> 意图识别（理解用户想做什么）

## 核心作用

识别：

- 用户意图 / 任务类型
- 业务线 / 主题 / 角色
- 输出要求 / 约束等

## 主角

```text
意图识别模型（LLM）
```

也就是说，意图识别本身可以借助大模型完成。

---

# 十三、② Workflow编排

## 标题

> Workflow编排（决定怎么做）

## 核心作用

- 选择合适的Workflow
- 确定整体步骤与顺序
- 识别条件分支 / 循环等

## 主角

```text
Workflow引擎
```

核心问题：

> 根据用户意图，决定接下来应该按照什么流程完成任务。

---

# 十四、③ 步骤执行

## 标题

> 步骤执行（由Skill / Tool / Script完成）

## 核心作用

- 按步骤调用相关Skill
- 需要时调用Tool / Script
- 产生中间结果

## 主角

```text
Skill / Tool / Script
```

这意味着：

> Workflow决定“做哪些步骤”，具体步骤由Skill、Tool、Script等组件执行。

---

# 十五、④ 知识检索（RAG）

## 标题

> 知识检索（RAG）（获取相关企业知识）

## 核心作用

- 将查询转为向量
- 在知识库检索相关内容
- 重排（Rerank）
- 返回TopK结果

## 主角

```text
RAG检索引擎
```

典型链路：

```text
查询
↓
Embedding
↓
向量检索
↓
Rerank
↓
TopK相关知识
```

RAG主要解决：

> 从企业知识库中找到当前任务真正相关的企业知识。

---

# 二十一、⑩ 用户反馈与沉淀

## 标题


同时反馈可以回流到前面的执行过程，用于持续优化。

# 二十二、各要素在流程中的作用（核心总结）

原图给出的核心总结如下。

| 要素 | 核心作用 |
|---|---|
| 意图识别 | 理解用户需求，判断要做什么任务 |
| Workflow | 决定任务执行的步骤和流程 |
| Skill | 完成具体任务的方法和能力 |
| Tool | 调用外部工具完成服务实现操作 |
| Script | 执行固定逻辑或确定性任务 |
| RAG | 从企业知识库中检索相关企业知识 |
| Reference | 提供规范、模板、案例等参考资料 |
| Prompt | 把所有材料组织成大模型输入 |
| LLM | 理解并生成最终内容 |
| 质量检查 | 检验结果是否符合预期和业务要求 |

# 二十五、产品价值与闭环

平台最终形成一条持续优化的价值链：

```text
提升研发效率
减少重复劳动
        ↓
知识沉淀与复用
形成组织资产
        ↓
质量与规范统一
降低沟通成本
        ↓
持续学习与优化
结果越来越好
        ↓
数据驱动运营
量化效果与改进
```

原图表达的最终价值方向是：

1. 提升研发效率，减少重复劳动
2. 知识沉淀与复用，形成组织资产
3. 质量与规范统一，降低沟通成本
4. 持续学习与优化，结果越来越好
5. 数据驱动运营，量化效果与改进

# 二十八、整个平台的一句话理解

> **用户通过AI工作台用自然语言提出任务，系统先识别用户意图，再由Workflow决定怎么做，调用Skill、Tool、Script完成具体步骤，同时通过RAG获取企业知识、通过Reference补充规范和案例，再由Prompt构建器组织完整上下文交给LLM生成结果，经过质量检查后交付给用户；用户的评价、纠错和优秀内容继续沉淀到知识库和案例库，形成持续优化闭环。**

# 三十、给代码AI的核心理解

> 这是一个企业研发AI辅助平台。平台的核心不是单纯调用一个大模型，而是围绕企业知识和可复用AI能力构建完整的任务执行体系。用户从AI工作台以自然语言提出任务，意图识别负责理解“用户想做什么”，Workflow负责决定“应该怎么做”，Skill负责具体专业任务，Tool负责调用外部能力，Script负责确定性逻辑，RAG负责从企业知识库检索相关知识，Reference负责提供企业规范、模板、优秀案例和用户资料，Prompt负责把系统指令、用户需求、Reference和中间结果组织成模型输入，LLM负责生成结果，质量检查负责校验结果。最终通过结果处理交付给用户，再通过用户反馈、优秀内容和问题沉淀形成持续优化闭环。
